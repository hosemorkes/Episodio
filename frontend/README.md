# Episodio — фронтенд

Next.js 16 (App Router, TypeScript) + Tailwind CSS 4 + Framer Motion + Zustand. Mobile-first PWA, две темы (Nordic Twilight / Nordic Frost), русский и английский.

Источник дизайна: `docs/design_handoff_episodio/` (README, референсы `reference/*.dc.html`, скриншоты). Бренд: `docs/episodio-brand/` (значок, favicon, иконки PWA скопированы в `public/`).

## Запуск

```bash
cd frontend
npm install
npm run dev          # http://localhost:3000
```

Остальные команды: `npm run typecheck`, `npm test` (vitest), `npm run build` + `npm start`.

## Вход (логин и пароль из .env)

Страница `/login` проверяет данные на сервере (`/api/auth/login`) и берёт их из **корневого** `.env` проекта (`next.config.ts` подгружает его при старте). Добавь в `.env` (шаблон — в `.env.example`):

```ini
AUTH_LOGIN=твой_логин
AUTH_PASSWORD=твой_пароль
AUTH_SECRET=случайная_строка_от_32_символов
```

Секрет: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Без этих трёх переменных вход отвечает 503 («Вход не настроен»).

Если вход отвечает 503, хотя переменные заданы:

- перезапусти `npm run dev`: `.env` читается только при старте, на лету он не подхватывается;
- проверь, что значения без кавычек и без пробелов вокруг `=`, а `.env` лежит в корне проекта, а не в `frontend/`;
- пароль не короче 4 символов (проверка формы).

Как это работает:

- после входа ставится httpOnly-cookie `episodio_session` с подписью HMAC-SHA256 (срок 30 дней; «Запомнить меня» выключено — cookie до закрытия браузера);
- `src/proxy.ts` пускает на все страницы и в `/api/*` только с действующей сессией, остальных отправляет на `/login?next=…`;
- 5 неудачных попыток в минуту с одного адреса — ответ 429;
- `Secure` для cookie ставится только за https.

## Что сделано

Все 10 экранов из handoff: дашборд, каталог (обзор и «Моя библиотека», поиск, фильтры), детали, редактирование и новый тайтл (отдельные страницы), AI-чат, статистика с анимацией при каждом открытии (данные с сервера), лента с бесконечным скроллом, витрина (управление и публичная страница), настройки (тема, язык, бэкап и экспорт JSON/TXT/Excel), вход. Палитра Ctrl+K, свайпы по карточкам, открытие тайтла в новой вкладке или окне (Ctrl/Cmd/Shift-клик или средняя кнопка мыши), «+» с пружинной анимацией, скелетоны до загрузки данных, PWA (манифест + service worker).

Отличия от прототипа:

- акцент светлой темы — `#0F766E` вместо `#0D9488` (контраст ≥4.5:1, как рекомендует handoff);
- нет `maskable`-иконки: в брендовом наборе её нет, в манифесте только `any`-иконки 192/512;
- на дашборде «Мои тайтлы» — сетка (как в README handoff), а не горизонтальная лента: иначе свайп по карточке конфликтует с прокруткой. В ней последние 12 изменённых карточек (сервер отдаёт записи по `updated_at`, только что тронутая идёт первой); вся библиотека — в «Каталоге». Блок «Всего серий» без пересчёта в часы, цифра по центру. В карточке «Продолжить» показываются сезон (у сериалов, аниме, мультсериалов, ТВ-шоу) и том (у манги, книг, аудиокниг), если он указан;
- постер при выборе файла уменьшается до 480 px (JPEG) и при сохранении загружается на сервер (`POST /items/{id}/poster`);
- валидация формы редактирования показывает ошибки под полями (название, числа ≥0, просмотрено ≤ всего, ссылка начинается с http:// или https://); «Всего» можно оставить пустым (идущий сериал), тогда прогресс показывается как «5», а не «5 / 12»;
- все 8 категорий БД есть в интерфейсе: аниме, мультсериал, сериал, фильм, ТВ-шоу, манга, книга, аудиокнига; у манги, книг и аудиокниг есть поле «Том»;
- на странице деталей есть блоки «Статус», «Сезон» (аниме, мультсериалы, сериалы, ТВ-шоу), «Том» (манга, книги, аудиокниги), «Ваш прогресс», «Ваша оценка», «Заметка». Сезон и том меняются кнопками − и +; без тома показывается «—». Поля сохраняются тем же способом, что и правка карточки;
- в карточке показываются автор, озвучка и ссылка на источник; вместо отзывов — одна личная заметка (в хранилище версии 1 первый отзыв автоматически становится заметкой);
- «Каталог» состоит из двух вкладок: «Моя библиотека» и «Требуют проверки». Раздел «Обзор» (полки, живой поиск по внешним каталогам) убран со страницы; хуки и функции для него (`useCatalogSearch`, `useCatalogPopular`, `shelves.ts`) остались в `src/lib`, поиск по внешним каталогам доступен через палитру Ctrl+K;
- оболочка с нижним меню (Дашборд, Каталог, AI, Статистика) показывается и на страницах тайтла (детали, редактирование, новый тайтл): внизу оставлен запас под меню;
- «← Назад к просмотру» из редактирования заменяет страницу в истории (`router.replace`), поэтому «← Назад» из деталей ведёт туда, откуда пришли, а не обратно в редактирование.

## Моя библиотека (Каталог)

- Над карточками: поиск по названию и оригинальному названию, кнопка «Фильтр» (показывает число активных фильтров) и пагинация.
- В панели «Фильтр»: статус, раздел (Все, Аниме, Мультсериал… с количеством тайтлов `Аниме · 12`; числа учитывают статус, жанры и поиск) и жанры (несколько сразу, тайтл должен содержать все выбранные; рядом число тайтлов с жанром). «Сбросить» очищает статус, раздел и жанры, но не поиск.
- Пагинация: 20, 50, 100 или «Все» (по умолчанию 20), кнопки ← / → и счётчик «1 / 3». Показывается и над карточками, и под ними, когда тайтлов больше 20. Любое изменение фильтров возвращает на первую страницу.

## Ручное обогащение

Недостающие данные карточки (постер, жанры, страна, год, автор, русское описание) подтягиваются из внешних источников через бэкенд (`GET /items/{id}/enrich/candidates`, `POST /items/{id}/enrich/apply`).

- На странице тайтла кнопка «Найти данные» открывает окно `EnrichModal` с вариантами: постер, название, год, источник (TMDB, Shikimori, Open Library), страна, жанры. Выбранный вариант заполняет **только пустые поля**; после применения показывается тост «Заполнено: постер, жанры» (или «Новых данных нет»).
- Чекбокс «Заменить постер» виден, если у тайтла уже есть постер, и отправляет `force=true`: заменяется только постер.
- Ошибки показываются текстом сервера. 400 (категория не поддерживается) и 503 (не задан ключ, например `TMDB_API_KEY`) повтором не лечатся, поэтому кнопки «Повторить» нет. При 502, 504 и обрыве связи она есть. 404 («вариант пропал из выдачи») обновляет список вариантов.
- В «Каталоге» есть вкладка «Требуют проверки»: записи без постера, жанров, страны или года (по 30 за раз, с фильтром по типу) и кнопка «Найти данные» у каждой. Список строится по библиотеке в браузере; `data/enrich_review.json` интерфейс не читает.
- Без `TMDB_API_KEY` сериалы, мультсериалы, ТВ-шоу и фильмы получают 503. Аниме и манга (Shikimori) и книги (Open Library) работают без ключа.

## AI-компаньон «Эпи»

Экран `/ai` подключён к бэкенду (DeepSeek, функции чтения библиотеки, веб-поиск Tavily; настройка — в корневом [README](../README.md#ai-компаньон-эпи)).

- Диалоги хранятся на сервере: кнопка «Диалоги» открывает список, «Новый чат» начинает чистый (диалог создаётся при первой реплике). При входе открывается последний диалог (до 30 последних реплик).
- Ответ приходит потоком SSE: `api.streamAiMessage` читает `ReadableStream`, `sse.ts` собирает события из кусков, текст дописывается в пузырь по мере прихода. Пока Эпи вызывает инструменты, показывается спиннер с подписью («Смотрю вашу библиотеку…», «Ищу в интернете…»). Лента сама прокручивается вниз.
- В пустом диалоге три подсказки: «Что посмотреть под чак-чак?», «Новости релизов аниме», «Анализ моих вкусов».
- Эпи только читает данные: просьбу изменить статус или добавить тайтл она объяснит словами (карточка или Ctrl+K).
- Прокси `/api/backend/*` отдаёт тело ответа потоком без буфера и обрывает запрос к FastAPI, если вкладку закрыли.

## Что дальше

Открытых этапов по «Эпи» нет; идеи: рендер Markdown в ответах, кнопка «Стоп» во время генерации.

## Витрины

Витрина — публичная страница «мой топ»: завершённые тайтлы с оценкой, отсортированные по оценке. Параметры: тип (или все), год и месяц завершения (по `finished_at`), число мест (4, 8, 12 или 20), название. Данные и правила выборки на сервере (подробнее: корневой [README](../README.md#витрины)).

**Управление (экран «Витрина», нужен вход).**

- Вкладки со списком витрин (точка показывает, публичная она или скрыта) и «+ Новая витрина». Редактор: название (пустое — подставляется «Мой топ аниме 2026, март» и т. п.), тип, год, месяц, число мест.
- Предпросмотр обновляется сам через 0,35 секунды после изменения (`POST /showcases/preview`, хук `useShowcasePreview`) и не требует сохранения. Если за период нет подходящих записей, подсказка объясняет, что в топ попадают завершённые тайтлы с оценкой и датой завершения.
- «Поделиться» сохраняет витрину (если есть несохранённые изменения), делает её публичной и копирует ссылку `<адрес сайта>/u/<имя>/<адрес>`. Если буфер обмена недоступен (например, не https), ссылка показывается в сообщении. «Скопировать ссылку» появляется у уже опубликованной. «Открыть» ведёт на публичную страницу, «Отключить» закрывает ссылку (витрина остаётся в списке), «Удалить» удаляет с подтверждением.
- Новая витрина всегда создаётся скрытой, публичной она становится только по «Поделиться».

**Публичная страница `/u/<имя>/<адрес>`** (серверный компонент `PublicShowcase`, без входа и без доступа к библиотеке):

- Только то, что пришло в ответе `ShowcaseItem`: названия, год, жанры, страна, автор, оценка, постер. Заметок, ссылок, озвучки и прогресса в страницу не попадает.
- Сервер Next.js сам ходит в FastAPI с ключом (`fetchPublicShowcase`), браузер к API не обращается. Скрытая и несуществующая витрина дают одинаковую страницу 404, как и чужое имя в ссылке.
- Постеры идут через `/u/<имя>/<адрес>/poster/<файл>` (маршрут также открыт без входа): он пересылает файл только если FastAPI считает его постером записи этой публичной витрины. Внешние постеры показываются прямо с их адреса.
- Превью ссылки: `og:title`, `og:description` («Топ из N: 1. …»), `og:url`, `og:image` (первый постер, адрес абсолютный: по заголовкам `x-forwarded-*` или `host`), Twitter-карточка. `?lang=en` включает английский интерфейс страницы. Поисковикам страница закрыта (`noindex`).
- Имя владельца в ссылке: `PUBLIC_HANDLE` из `.env` (по умолчанию `me`). Это не логин для входа, логин в публичные ссылки не попадает.
- Единственное исключение из защиты `src/proxy.ts`: адреса вида `/u/<имя>/<адрес>` и `/u/<имя>/<адрес>/poster/<файл>` (`isPublicPath`, строгая проверка, покрыта тестами). На публичных страницах библиотека не загружается: иначе у посетителя была бы 401 и переход на вход.

## Экспорт и резервная копия

В «Настройках → Данные»:

- **Экспорт в Excel** и **Экспорт в JSON** собирает сервер (`GET /export`, функция `downloadExport` в `src/lib/api.ts`): выгружается вся библиотека из базы, а не только загруженная в браузер. Excel: первый лист «Все» (вся библиотека, столбец «Тип») и лист на категорию, русские заголовки, настоящие даты, подробнее в корневом [README](../README.md#экспорт). Имя файла приходит от сервера (`episodio-ГГГГ-ММ-ДД.xlsx`), прокси пересылает заголовок `Content-Disposition`; на время подготовки кнопка недоступна и показывает «Готовлю файл…». Ошибки показываются тостом, закончившаяся сессия ведёт на вход.
- **Экспорт в TXT** по-прежнему собирается в браузере по библиотеке из стора (`exportRows` в `src/lib/rules.ts`).
- **Сохранить базу данных** и **Восстановить из файла**: копия в формате интерфейса собирается в браузере. Восстановление принимает и её, и серверный JSON-экспорт (`fromServerExport` приводит записи API к виду интерфейса); журнал из файла не восстанавливается.
- Старый «Excel» (HTML с расширением `.xls`) удалён. Если браузер скачал `.xls`, это устаревшая версия интерфейса в кэше: обнови страницу через Ctrl+Shift+R.
- Под кнопками экспорта в настройках подпись: Excel и TXT для восстановления не подходят (восстанавливать можно из JSON-копии интерфейса, серверного JSON-экспорта или дампа `pg_dump`, см. корневой [README](../README.md#скрипты)).

## Статистика

Экран «Статистика» и график «Эта неделя» на главной берут данные с сервера (`GET /stats`, хук `useStats`).

- Запрос идёт за текущую неделю с понедельника по воскресенье (даты по местному времени, `weekRange` в `src/lib/stats.ts`). Ответ лежит в сторе (`stats`, `statsError`) и не сохраняется в localStorage.
- Статистика обновляется после загрузки библиотеки и при изменениях: когда добавляется или удаляется запись и когда в ленте появляется или пропадает отметка (в том числе когда временная запись получает id от сервера, то есть после записи в БД). Ответ на устаревший запрос отбрасывается.
- «Жанры», «Страны», «Годы выхода», «Топ по сериям» и «Оценки» считаются на клиенте по копии библиотеки в сторе (`libraryBreakdown`, `ratingBreakdown` в `src/lib/stats.ts`), а не берутся из ответа `/stats`: так сразу видны новые жанры (сервер отдаёт не больше 10) и работает выбор раздела. В заголовке каждого блока выпадающий список раздела (Все, Аниме, Мультсериал, Сериал, Фильм, ТВ-шоу, Манга, Книга, Аудиокнига), у блоков он свой. Жанры, страны и годы считаются по числу тайтлов (каждая карточка = 1), заглушки «Без жанра», страна «—» и год 0 не учитываются. «Топ по сериям» — по накопленному прогрессу (серии или главы, просмотренный фильм = 1), 5 записей; стран показывается 10. Круг жанров занимает всю ширину блока, в легенде все жанры. Блок «Оценки»: средняя оценка, число тайтлов с оценкой и без, столбцы по оценкам 1–10. Сервер по-прежнему нужен для недели, итогов и признака «библиотека пуста». Анимация запускается, когда данные есть.
- «Эта неделя»: реальные отметки журнала по дням. Сегодняшний столбик не отстаёт от только что нажатого «+» (берётся большее из ответа сервера и локальной ленты). Высота столбцов масштабируется по максимуму недели (не меньше 4).
- «Всего серий» не включает главы и фильмы. Главы показываются отдельной строкой «Прочитано глав», а «≈ часов просмотра» считаются только по сериям. Итоги на главной считаются по копии библиотеки в сторе (`totalsOf`), чтобы счётчик менялся сразу после «+»; правила те же, что у `totals` в `/stats`.
- Пустая библиотека: вместо пустых графиков «Пока нечего считать». Если записи есть, а отмеченного прогресса нет, диаграммы заполнены, а в блоке топа написано «Пока нет отмеченных серий и глав». Если сервер не ответил, на экране «Статистика» показывается текст ошибки и кнопка «Повторить».

## Источники: Shikimori и AniList

> Блоки «Поиск по каталогам» и «Полки Обзора» ниже описывают экран «Обзор», который убран со страницы «Каталог» (код хуков остался в `src/lib`). Живой поиск в каталогах теперь доступен через палитру Ctrl+K.

У аниме и манги два источника (Shikimori по умолчанию, AniList ключа не требует). Раньше в «Каталоге → Обзор» на вкладках «Аниме» и «Манга» появлялся выбор «Источник», он применяется к поиску и к полкам. В окне «Найти данные» тот же выбор: варианты берутся из выбранного источника, а применение вызывается с его `source`. Для остальных типов выбирать нечего (список источников в `sourcesFor`, `src/lib/enrich.ts`, зеркалит реестр бэкенда). У AniList названия английские или ромадзи, жанры переведены в те же названия, что у Shikimori.

## Поиск по каталогам

В «Каталоге → Обзор» строка поиска ищет не только по статической подборке, но и во внешних каталогах через бэкенд (`GET /catalog/search`): TMDB (сериалы, мультсериалы, ТВ-шоу, фильмы), Shikimori (аниме, манга), Open Library (книги, аудиокниги).

- Запрос уходит через 0,6 секунды после последнего нажатия, минимум 2 символа; устаревшие ответы отбрасываются (хук `useCatalogSearch` в `src/lib/useCatalogSearch.ts`).
- Вкладка типа сужает поиск до одной категории; на вкладке «Все» ищется по основным (аниме, сериалы, фильмы, манга, книги).
- Результаты показываются карточками с внешним постером и бейджем источника (TMDB, Shikimori, Open Library). Выше идёт блок «Найдено в каталогах», ниже «В подборке» (совпадения в статической подборке).
- Кнопка «+ Добавить» открывает меню статуса и вызывает `POST /items/from-catalog`: сервер создаёт запись, скачивает постер и подгружает жанры. Если тайтл уже в библиотеке, кнопка показывает «В библиотеке» и ведёт на карточку; попытка добавить дубликат даёт сообщение сервера.
- Если часть источников недоступна (например, не задан `TMDB_API_KEY`), показываются результаты остальных и подпись «Часть источников недоступна: …». Если не ответил ни один, вместо результатов красная плашка с причиной.
- Фильтры работают с живой подборкой, когда она загружена (жанры берутся из самой подборки), а фильтр «Статус выхода» в этом режиме скрыт: у внешних источников статуса выхода нет. Если подборка недоступна, фильтры действуют на статическую.

## Полки «Обзора»

Полки и баннеры берутся с сервера (`GET /catalog/popular`, хук `useCatalogPopular`) по выбранной вкладке типа: TMDB (популярное по фильмам, сериалам, мультсериалам и ТВ-шоу), Shikimori (по популярности для аниме и манги), Open Library (книги недели).

- Полки: «Популярное сейчас» (на вкладке «Все» категории чередуются), до двух полок «Топ в жанре …» (жанр с тремя и более оценёнными тайтлами, по оценке источника) и «AI рекомендует вам» (то, чего нет в библиотеке, по совпадению жанров с вашими). Баннеры карусели: первые пять с постером. Логика в `src/lib/shelves.ts` (чистые функции с тестами).
- Фильтры по жанру (все выбранные сразу), году и сортировка («По популярности» сохраняет порядок сервера, «По рейтингу», «Новинки») применяются к ответу. Жанры в панели фильтров берутся из самой подборки: у разных источников они называются по-разному.
- Подборка кэшируется: на сервере час, в браузере 10 минут (`src/lib/ttl-cache.ts`), поэтому смена вкладок не дёргает внешние API.
- Если подборку получить не удалось (например, нет `TMDB_API_KEY` для вкладки «Сериалы»), показывается прежняя статическая из `catalog-data.ts` и строка «Живая подборка недоступна, показана базовая» с кнопкой «Повторить». Если часть источников не ответила, остальные показываются с подписью «Часть источников недоступна».
- У Shikimori в списке нет жанров, поэтому на вкладках «Аниме» и «Манга» полок по жанрам и рекомендаций нет; оценка (★) приходит у TMDB и Shikimori, у Open Library её нет.

## Палитра Ctrl+K: добавление из каталога

Если в строке палитры не меньше двух символов, после обычных действий появляются результаты живого поиска (до пяти): «Добавить: название (год)». Выбор добавляет тайтл в «В планах» тем же способом, что кнопка в каталоге (`POST /items/from-catalog`: постер, жанры, общее число серий или глав). Строка «Добавить тайтл «…»» по-прежнему открывает пустую форму.

## Данные и синхронизация

Источник правды — база на сервере. Демо-данные из localStorage не переносятся: библиотека начинается с пустой БД, нужный список загружается скриптом `python -m scripts.import_json`. В localStorage остаются только настройки (тема, язык), время последней копии и id карточки «Продолжить».

Как ведёт себя `src/lib/store.ts`:

- **Загрузка.** После входа оболочка приложения (`AppShell`) вызывает `ensureLoaded()`: с сервера приходят вся библиотека (страницами по 200 записей до неполной страницы, без потолка) и первая страница ленты (20 записей). До ответа страницы показывают скелетоны. Если сервер недоступен, вверху появляется красная плашка с кнопкой «Повторить». На странице входа данные не грузятся (нет сессии).
- **Оптимистичные действия.** «+», «−», смена статуса, оценка, заметка и удаление меняют интерфейс сразу, а на сервер уходят в фоне. «+» и «−» идут через `POST /items/{id}/progress`, сервер сам меняет статус и ведёт журнал, а временная запись ленты заменяется настоящей.
- **Очередь по тайтлу.** Запросы к одному тайтлу выполняются строго по очереди, поэтому быстрые нажатия не обгоняют друг друга, а ответ сервера применяется к карточке, только если в очереди нет более новых действий (иначе счётчик «прыгал» бы назад).
- **Ошибки.** Если запрос не удался, показывается тост с текстом ошибки, а карточка и лента перечитываются с сервера: интерфейс не расходится с БД. Если сессия закончилась (401), происходит переход на `/login`.
- **Фильм.** У него нет счётчика: «Отметить просмотр» ставит статус `completed`, а запись в ленте создаёт сервер. «−» у просмотренного фильма возвращает его в «В планах».
- **Создание и правка** (форма, «Добавить из каталога») не оптимистичные: id выдаёт БД, поэтому интерфейс ждёт ответа (кнопка показывает спиннер). Новый постер загружается после сохранения; если он не загрузился, тайтл всё равно сохраняется и показывается тост.
- **Лента** подгружается порциями при прокрутке (`GET /log?before=<id последней записи>`).
- **Восстановление из копии** (Настройки) загружает на сервер недостающие записи; уже существующие (то же название и тип) пропускает, а записи со старым форматом (отзывы, страницы книг) приводит к новому. Журнал просмотров из файла не восстанавливается, его ведёт сервер.
- **Статусы как на сервере.** Отметка серии у «брошенного» тайтла статус не меняет (сервер так же), у «в планах» и «просмотрено» переводит в «смотрю», на последней серии ставит «просмотрено».
- **Статус не меняет прогресс.** Смена статуса вручную (блок «Статус» на странице деталей) меняет только статус: «В планах» не обнуляет серии, «Просмотрено» не дописывает их до конца. Исключение — фильм: у него нет счётчика, «просмотрен» определяется статусом. Обратное направление (отметка «+» переводит статус) осталось, его делает сервер.
- **Повторы.** При создании и правке тайтла форма ищет в библиотеке тот же тип с тем же названием или оригинальным названием (без учёта регистра и пробелов, `findDuplicate` в `rules.ts`). Если нашла, показывается плашка со ссылкой «Открыть ↗», первое нажатие «Сохранить» только предупреждает, а кнопка превращается в «Всё равно сохранить». Добавление из каталога и палитры повторы отклоняет сервер (409).

Известные ограничения: офлайн-режима нет, а при нескольких открытых вкладках изменения подтягиваются только после перезагрузки. Запись с категорией, которой интерфейс не знает (новая на сервере), показывается как «сериал»; если сохранить такую запись через форму, её категория в БД станет `tv_series`.

## Связь с бэкендом

Браузер ходит не в FastAPI, а в свой Next.js: `src/app/api/backend/[...path]/route.ts` пересылает запрос в FastAPI и подставляет заголовок `X-API-Key`. Ключ живёт только на сервере Next.js, в браузер не попадает. Прокси пускает только с действующей сессией (её проверяет `src/proxy.ts`) и только в разделы `items`, `genres`, `log`, `stats`, `showcases`, `export`, `catalog`, `ai`, `posters` и `health`; остальное (`/docs`, `/openapi.json`) закрыто. Постеры из БД (`/posters/42.jpg`) показываются тем же путём: `/api/backend/posters/42.jpg`.

Настройки в корневом `.env` (шаблон — `.env.example`):

| Переменная | Для чего |
| --- | --- |
| `API_URL` | Адрес FastAPI, по умолчанию `http://127.0.0.1:8000` |
| `API_KEY` | Общий секрет. Тот же, что у бэкенда: если он там задан, без ключа API отвечает 401. Если не задан, оставь пустым |
| `PUBLIC_HANDLE` | Имя владельца в публичных ссылках `/u/<имя>/…` (по умолчанию `me`) |

Как устроен `src/lib/api.ts`:

- **Адаптеры** (чистые функции, покрыты тестами): `toTitle` (БД → карточка интерфейса), `toApiFields` (карточка → поля БД для POST и PATCH), `toLogEntry` (запись журнала → строка ленты), `toCatalogResult`, `toEnrichCandidate`, `toStats`, `toShowcase`, `toShowcaseView`. Категория, которой интерфейс не знает, превращается в «сериал» (`typeFromApi`), запись остаётся видимой.
- **Клиент `api`**: `listItems`, `getItem`, `createItem`, `updateItem`, `patchItem`, `deleteItem`, `progress` (±1 серия или глава), `listLog`, `getStats`, `listGenres`, `searchCatalog`, `popularCatalog`, `addFromCatalog`, `listCandidates`, `applyCandidate`, `listConversations`, `createConversation`, `listAiMessages`, `streamAiMessage` (SSE), `downloadExport`, `listShowcases`, `createShowcase`, `updateShowcase`, `deleteShowcase`, `previewShowcase`, `uploadPoster`, `deletePoster`. Ошибки приходят как `ApiError` с кодом и текстом.
- **Таймауты.** Обычный запрос ждёт 15 секунд, загрузка файла 60, поиск и применение вариантов обогащения 45 (они ходят во внешние API). Зависший сервер даёт `ApiError` со статусом 0 и текстом «Сервер не ответил вовремя».

Соответствие значений:

| Интерфейс | БД |
| --- | --- |
| `anime`, `cartoon`, `movie`, `manga`, `book`, `audiobook` | такие же |
| `series` | `tv_series` |
| `show` | `tv_show` |
| статус `done` | `completed` (остальные совпадают) |
| оценка `0` | `NULL` (иначе 1–10) |
| `ep` / `tot` у сериалов | `current_episode` / `total_episodes` |
| `ep` / `tot` у манги, книг, аудиокниг | `current_chapter` / `total_chapters` |
| фильм `ep` 0/1 | не хранится, считается по статусу |
| `tot = 0` | `NULL`: общее число неизвестно |
| жанры с заглавной («Драма») | в нижнем регистре («драма»); заглушка «Без жанра» в БД не пишется |
| `note` | `comment` (одна заметка вместо отзывов) |
| `vol`, `author`, `tr`, `link` | `current_volume`, `author`, `translation`, `source_link` |

Страниц у книг больше нет: прогресс книг, манги и аудиокниг считается по главам, а том указывается отдельно.
