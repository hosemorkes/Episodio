# Episodio — фронтенд

Next.js 16 (App Router, TypeScript) + Tailwind CSS 4 + Framer Motion + Zustand. Mobile-first PWA, две темы (Nordic Twilight / Nordic Frost), русский и английский.

Источник дизайна: `docs/design_handoff_episodio/` (README, референсы `reference/*.dc.html`, скриншоты). Бренд: `docs/episodio-brand/` (значок, favicon, иконки PWA скопированы в `public/`).

## Запуск

```bash
cd frontend
npm install
npm run dev          # http://localhost:3000
```

Остальные команды: `npm run typecheck`, `npm test` (vitest), `npm run build` + `npm start`.

## Вход (логин и пароль из .env)

Страница `/login` проверяет данные на сервере (`/api/auth/login`) и берёт их из **корневого** `.env` проекта (`next.config.ts` подгружает его при старте). Добавь в `.env` (шаблон — в `.env.example`):

```
AUTH_LOGIN=твой_логин
AUTH_PASSWORD=твой_пароль
AUTH_SECRET=случайная_строка_от_32_символов
```

Секрет: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Без этих трёх переменных вход отвечает 503 («Вход не настроен»).

Если вход отвечает 503, хотя переменные заданы:

- перезапусти `npm run dev`: `.env` читается только при старте, на лету он не подхватывается;
- проверь, что значения без кавычек и без пробелов вокруг `=`, а `.env` лежит в корне проекта, а не в `frontend/`;
- пароль не короче 4 символов (проверка формы).

Как это работает:

- после входа ставится httpOnly-cookie `episodio_session` с подписью HMAC-SHA256 (срок 30 дней; «Запомнить меня» выключено — cookie до закрытия браузера);
- `src/proxy.ts` пускает на все страницы и в `/api/*` только с действующей сессией, остальных отправляет на `/login?next=…`;
- 5 неудачных попыток в минуту с одного адреса — ответ 429;
- `Secure` для cookie ставится только за https.

## Что сделано

Все 10 экранов из handoff: дашборд, каталог (обзор и «Моя библиотека», поиск, фильтры), детали, редактирование и новый тайтл (отдельные страницы), AI-чат, статистика с анимацией при каждом открытии, лента с бесконечным скроллом, витрина, настройки (тема, язык, бэкап и экспорт JSON/TXT/Excel), вход. Палитра Ctrl+K, свайпы по карточкам, «+» с пружинной анимацией, скелетоны до загрузки данных, PWA (манифест + service worker).

Отличия от прототипа:

- акцент светлой темы — `#0F766E` вместо `#0D9488` (контраст ≥4.5:1, как рекомендует handoff);
- нет `maskable`-иконки: в брендовом наборе её нет, в манифесте только `any`-иконки 192/512;
- на дашборде «Мои тайтлы» — сетка (как в README handoff), а не горизонтальная лента: иначе свайп по карточке конфликтует с прокруткой;
- постер при выборе файла уменьшается до 480 px (JPEG) и при сохранении загружается на сервер (`POST /items/{id}/poster`);
- валидация формы редактирования показывает ошибки под полями (название, числа ≥0, просмотрено ≤ всего, всего ≥1, ссылка начинается с http:// или https://);
- все 8 категорий БД есть в интерфейсе: аниме, мультсериал, сериал, фильм, ТВ-шоу, манга, книга, аудиокнига; у манги, книг и аудиокниг есть поле «Том»;
- в карточке показываются автор, озвучка и ссылка на источник; вместо отзывов — одна личная заметка (в хранилище версии 1 первый отзыв автоматически становится заметкой);
- вкладки в «Обзоре» и «Моей библиотеке» включают все 8 категорий; у «Обзора» полки статические, а поиск живой (см. «Поиск по каталогам»).

## Что дальше

Полки «Обзора» (популярное, топ по жанру, рекомендации) пока статические: у внешних источников нет готовых подборок, поэтому для них нужен отдельный эндпоинт (например, `GET /catalog/popular`) или собственная выборка. Статистика и витрина всё ещё считаются на клиенте по загруженной библиотеке (витрина — на демо-данных; для неё на сервере уже есть `finished_at`). «Эпи» отвечает по правилам — позже LLM с контекстом библиотеки. Публичные витрины (`/u/[user]/…`) и серверный экспорт `.xlsx` — тоже впереди.

## Поиск по каталогам

В «Каталоге → Обзор» строка поиска ищет не только по статической подборке, но и во внешних каталогах через бэкенд (`GET /catalog/search`): TMDB (сериалы, мультсериалы, ТВ-шоу, фильмы), Shikimori (аниме, манга), Open Library (книги, аудиокниги).

- Запрос уходит через 0,6 секунды после последнего нажатия, минимум 2 символа; устаревшие ответы отбрасываются (хук `useCatalogSearch` в `src/lib/useCatalogSearch.ts`).
- Вкладка типа сужает поиск до одной категории; на вкладке «Все» ищется по основным (аниме, сериалы, фильмы, манга, книги).
- Результаты показываются карточками с внешним постером и бейджем источника (TMDB, Shikimori, Open Library). Выше идёт блок «Найдено в каталогах», ниже «В подборке» (совпадения в статической подборке).
- Кнопка «+ Добавить» открывает меню статуса и вызывает `POST /items/from-catalog`: сервер создаёт запись, скачивает постер и подгружает жанры. Если тайтл уже в библиотеке, кнопка показывает «В библиотеке» и ведёт на карточку; попытка добавить дубликат даёт сообщение сервера.
- Если часть источников недоступна (например, не задан `TMDB_API_KEY`), показываются результаты остальных и подпись «Часть источников недоступна: …». Если не ответил ни один, вместо результатов красная плашка с причиной.
- Фильтры (жанры, год, статус выхода, сортировка) относятся только к статической подборке: внешние источники их не поддерживают.

## Данные и синхронизация

Источник правды — база на сервере. Демо-данные из localStorage не переносятся: библиотека начинается с пустой БД, нужный список загружается скриптом `python -m scripts.import_json`. В localStorage остаются только настройки (тема, язык), время последней копии и id карточки «Продолжить».

Как ведёт себя `src/lib/store.ts`:

- **Загрузка.** После входа оболочка приложения (`AppShell`) вызывает `ensureLoaded()`: с сервера приходят вся библиотека и первая страница ленты (20 записей). До ответа страницы показывают скелетоны. Если сервер недоступен, вверху появляется красная плашка с кнопкой «Повторить». На странице входа данные не грузятся (нет сессии).
- **Оптимистичные действия.** «+», «−», смена статуса, оценка, заметка и удаление меняют интерфейс сразу, а на сервер уходят в фоне. «+» и «−» идут через `POST /items/{id}/progress`, сервер сам меняет статус и ведёт журнал, а временная запись ленты заменяется настоящей.
- **Очередь по тайтлу.** Запросы к одному тайтлу выполняются строго по очереди, поэтому быстрые нажатия не обгоняют друг друга, а ответ сервера применяется к карточке, только если в очереди нет более новых действий (иначе счётчик «прыгал» бы назад).
- **Ошибки.** Если запрос не удался, показывается тост с текстом ошибки, а карточка и лента перечитываются с сервера: интерфейс не расходится с БД. Если сессия закончилась (401), происходит переход на `/login`.
- **Фильм.** У него нет счётчика: «Отметить просмотр» ставит статус `completed`, а запись в ленте создаёт сервер. «−» у просмотренного фильма возвращает его в «В планах».
- **Создание и правка** (форма, «Добавить из каталога») не оптимистичные: id выдаёт БД, поэтому интерфейс ждёт ответа (кнопка показывает спиннер). Новый постер загружается после сохранения; если он не загрузился, тайтл всё равно сохраняется и показывается тост.
- **Лента** подгружается порциями при прокрутке (`GET /log?before=<id последней записи>`).
- **Восстановление из копии** (Настройки) загружает на сервер недостающие записи; уже существующие (то же название и тип) пропускает, а записи со старым форматом (отзывы, страницы книг) приводит к новому. Журнал просмотров из файла не восстанавливается, его ведёт сервер.
- **Статусы как на сервере.** Отметка серии у «брошенного» тайтла статус не меняет (сервер так же), у «в планах» и «просмотрено» переводит в «смотрю», на последней серии ставит «просмотрено».

Известные ограничения: форма требует «Всего ≥ 1» (идущий сериал без известного числа серий нужно вносить с примерным числом, а сервер и интерфейс «Всего = 0/неизвестно» уже поддерживают), офлайн-режима нет, а при нескольких открытых вкладках изменения подтягиваются только после перезагрузки.

## Связь с бэкендом

Браузер ходит не в FastAPI, а в свой Next.js: `src/app/api/backend/[...path]/route.ts` пересылает запрос в FastAPI и подставляет заголовок `X-API-Key`. Ключ живёт только на сервере Next.js, в браузер не попадает. Прокси пускает только с действующей сессией (её проверяет `src/proxy.ts`) и только в разделы `items`, `genres`, `log`, `posters` и `health`; остальное (`/docs`, `/openapi.json`) закрыто. Постеры из БД (`/posters/42.jpg`) показываются тем же путём: `/api/backend/posters/42.jpg`.

Настройки в корневом `.env` (шаблон — `.env.example`):

| Переменная | Для чего |
| --- | --- |
| `API_URL` | Адрес FastAPI, по умолчанию `http://127.0.0.1:8000` |
| `API_KEY` | Общий секрет. Тот же, что у бэкенда: если он там задан, без ключа API отвечает 401. Если не задан, оставь пустым |

Как устроен `src/lib/api.ts`:

- **Адаптеры** (чистые функции, покрыты тестами): `toTitle` (БД → карточка интерфейса), `toApiFields` (карточка → поля БД для POST и PATCH), `toLogEntry` (запись журнала → строка ленты).
- **Клиент `api`**: `listItems`, `getItem`, `createItem`, `updateItem`, `patchItem`, `deleteItem`, `progress` (±1 серия или глава), `listLog`, `listGenres`, `searchCatalog`, `addFromCatalog`, `uploadPoster`, `deletePoster`. Ошибки приходят как `ApiError` с кодом и текстом.

Соответствие значений:

| Интерфейс | БД |
| --- | --- |
| `anime`, `cartoon`, `movie`, `manga`, `book`, `audiobook` | такие же |
| `series` | `tv_series` |
| `show` | `tv_show` |
| статус `done` | `completed` (остальные совпадают) |
| оценка `0` | `NULL` (иначе 1–10) |
| `ep` / `tot` у сериалов | `current_episode` / `total_episodes` |
| `ep` / `tot` у манги, книг, аудиокниг | `current_chapter` / `total_chapters` |
| фильм `ep` 0/1 | не хранится, считается по статусу |
| `tot = 0` | `NULL`: общее число неизвестно |
| жанры с заглавной («Драма») | в нижнем регистре («драма»); заглушка «Без жанра» в БД не пишется |
| `note` | `comment` (одна заметка вместо отзывов) |
| `vol`, `author`, `tr`, `link` | `current_volume`, `author`, `translation`, `source_link` |

Страниц у книг больше нет: прогресс книг, манги и аудиокниг считается по главам, а том указывается отдельно.
