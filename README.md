# Episodio

Episodio — личное хранилище для аниме, мультсериалов, сериалов, фильмов, телепередач, манги, книг и аудиокниг. Оно помогает отслеживать, что ты смотришь и читаешь: статус, текущий сезон и серию или том и главу, личную оценку, заметки, постеры и ссылки на источники.

Проект рассчитан на одного пользователя. Бэкенд написан на FastAPI с PostgreSQL. Старый список из блокнотов один раз загружается из JSON. Веб-интерфейс (Next.js) лежит в `frontend/` и работает с этим API через серверный прокси (см. [Фронтенд](#фронтенд)); договорённости между ними описаны в [docs/api-contract.md](docs/api-contract.md).

## Требования

- Python 3.12 или новее
- PostgreSQL 16 или новее, установленный локально

## Быстрый старт

1. Клонируй репозиторий и перейди в его папку.

2. Создай виртуальное окружение и активируй его.

   ```powershell
   # Windows (PowerShell)
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   ```

   ```bash
   # macOS / Linux
   python3 -m venv .venv
   source .venv/bin/activate
   ```

3. Установи зависимости:

   ```bash
   pip install -r requirements-dev.txt
   ```

4. Создай файл настроек и впиши в `.env` свои параметры подключения к PostgreSQL:

   ```bash
   cp .env.example .env
   ```

   Подключение задаётся ключами `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`. Вместо них можно указать одну строку `DATABASE_URL` (она имеет приоритет). `TEST_DATABASE_URL` нужна для тестов, она обязательно должна указывать на другую базу. Файл `.env` в git не попадает.

5. Убедись, что PostgreSQL запущен, и создай две пустые базы: рабочую и тестовую (имена как в `.env`):

   ```bash
   psql -U postgres -c "CREATE DATABASE episodio_db;"
   psql -U postgres -c "CREATE DATABASE episodio_test;"
   ```

6. Создай таблицу (команду можно запускать повторно):

   ```bash
   python -m scripts.init_db
   ```

7. Запусти API:

   ```bash
   uvicorn backend.main:app --reload --host 127.0.0.1
   ```

8. Открой <http://127.0.0.1:8000/docs>. Там интерактивная документация Swagger, в которой можно пробовать запросы без фронтенда.

Все команды выполняются из корня проекта.

Чтобы сбросить рабочую базу и создать таблицы заново, запусти `python -m scripts.init_db --reset`. Скрипт спросит подтверждение, потому что все данные в `media_items`, `progress_log` и `showcases` будут удалены.

Если база была создана до появления полей `description`, `total_episodes`, `total_chapters`, `finished_at` и таблиц `progress_log` и `showcases`, достаточно снова выполнить `python -m scripts.init_db`: схема добавит недостающее, существующие записи не затрагиваются.

## API

| Метод и путь | Что делает |
| --- | --- |
| `GET /health` | Проверка работы API и соединения с базой |
| `GET /items/` | Список записей. Фильтры: `category`, `status`, `genre`, `q` (поиск по названию). Сортировка: `sort` (`updated_at` по умолчанию, `created_at`, `finished_at`, `title_ru`, `release_year`, `rating`) и `order` (`desc` по умолчанию или `asc`); записи без значения идут в конце. Постранично: `limit` (1–500, по умолчанию все) и `offset` |
| `GET /genres` | Жанры, которые есть в базе (по алфавиту, в нижнем регистре). Необязательный фильтр `category` |
| `GET /items/{id}` | Одна запись |
| `POST /items/` | Добавить запись |
| `PATCH /items/{id}` | Изменить только переданные поля, например `{"current_episode": 6}` |
| `POST /items/{id}/progress` | Отметить серию или главу: `{"delta": 1}`, откатить: `{"delta": -1}`. Подробнее ниже |
| `GET /catalog/search` | Живой поиск по внешним каталогам (TMDB, Shikimori, Open Library): `q` (от 2 символов), `category`, `limit` (1–20 на категорию, по умолчанию 10). Ничего не сохраняет. Подробнее ниже |
| `GET /catalog/popular` | Популярное для полок «Обзора»: `category` (без неё — по основным категориям), `limit` (1–30 на категорию, по умолчанию 12). Ответ в том же формате, что у поиска, у результатов есть `rating`. Кэшируется на час. Подробнее ниже |
| `POST /items/from-catalog` | Добавить найденный в каталоге тайтл в библиотеку: тело — поля результата поиска и необязательный `status` (по умолчанию `planned`). Постер скачивается в `media/posters/`, жанры и общее число серий или глав подгружаются |
| `GET /log` | Лента активности: записи журнала, свежие первыми. Параметры: `limit` (1–100, по умолчанию 20), `before` (id последней записи прошлой страницы), `item_id` |
| `GET /export` | Выгрузка библиотеки файлом: `format=xlsx` (Excel, по умолчанию) или `format=json`. Подробнее ниже |
| `GET /stats` | Статистика: распределения по библиотеке и отметки журнала за период. Параметры: `from`, `to` (даты `YYYY-MM-DD`, включительно; по умолчанию последние 7 дней), `limit` (1–50, по умолчанию 10). Подробнее ниже |
| `GET /showcases`, `POST /showcases`, `PATCH /showcases/{id}`, `DELETE /showcases/{id}` | Управление витринами (публичными страницами «мой топ»). Подробнее ниже |
| `POST /showcases/preview` | Предпросмотр витрины по параметрам, ничего не сохраняя |
| `GET /public/showcases/{slug}` | Публичное содержимое витрины (только поля `ShowcaseItem`); 404 для неизвестной и отключённой |
| `GET /public/showcases/{slug}/posters/{файл}` | Постер записи, которая входит в эту публичную витрину |
| `DELETE /items/{id}` | Удалить запись (файл её постера тоже удаляется) |
| `POST /items/{id}/poster` | Загрузить свой постер: `image/jpeg`, `image/png` или `image/webp`, до 5 МБ. Файл сохраняется как `media/posters/{id}.ext`, в `poster_url` записывается `/posters/{id}.ext` |
| `DELETE /items/{id}/poster` | Удалить постер: файл и ссылку на него |
| `GET /posters/{имя файла}` | Отдаёт сохранённый постер |
| `GET /items/{id}/enrich/candidates` | Ищет запись во внешнем API (источник зависит от категории) и возвращает варианты для ручного выбора. Ничего не сохраняет |
| `POST /items/{id}/enrich/apply` | Применяет выбранный вариант: тело `{"source": "...", "external_id": "..."}`. Заполняет только пустые поля, скачивает постер, если его нет. С `?force=true` постер заменяется даже заполненный |

В `poster_url` можно вручную (через `PATCH`) записать и внешний URL.

### Поля записи

Помимо названия, категории, статуса, жанров, страны, года, автора, оценки, заметки (`comment`) и ссылок у записи есть:

| Поле | Что это |
| --- | --- |
| `description` | Описание |
| `current_season`, `current_episode` | Прогресс сериалов, аниме, мультсериалов и ТВ-шоу |
| `current_volume`, `current_chapter` | Прогресс манги, книг и аудиокниг |
| `total_episodes`, `total_chapters` | Сколько всего серий или глав (`NULL` — неизвестно; у фильма не заполняется) |
| `finished_at` | Когда запись стала `completed`. Только для чтения: время ставит триггер БД при переходе в `completed` и сбрасывает в `NULL` при любом другом статусе |

Жанры всегда хранятся и отдаются в нижнем регистре, без пустых значений и повторов (при записи через API, импорт и обогащение). Пустой список `[]` остаётся пустым.

### Прогресс и журнал

`POST /items/{id}/progress` меняет счётчик на ±1 и ведёт журнал `progress_log` (его читает `GET /log`). Ответ: `item` (обновлённая запись) и `entry` (запись журнала).

- **Какой счётчик меняется** зависит от категории: `anime`, `cartoon`, `tv_series`, `tv_show` — `current_episode` (сверяется с `total_episodes`), `manga`, `book`, `audiobook` — `current_chapter` (сверяется с `total_chapters`). Для `movie` отметки нет: ответ `400`, фильм отмечается сменой статуса.
- **`delta: 1`** добавляет запись в журнал с номером новой серии или главы. Когда число достигло `total_*`, статус становится `completed`; если запись была `planned` или `completed`, но не досмотрена, — `watching`. Если всё уже отмечено, ответ `409`.
- **`delta: -1`** уменьшает счётчик (не ниже 0; пустой `NULL` остаётся пустым) и удаляет последнюю запись журнала по этой записи, если она есть, иначе ошибки нет (`entry` будет `null`). Статус `completed` меняется на `watching`.
- **Фильм:** при переходе статуса в `completed` (в том числе при создании) в журнал пишется запись `movie` с номером 1, при возврате из `completed` последняя запись журнала удаляется.

Записи журнала удаляются вместе с записью (`ON DELETE CASCADE`).

### Статистика

`GET /stats?from=2026-10-19&to=2026-10-25` отдаёт всё для экрана «Статистика» и графика «Эта неделя» одним ответом. Период (`from`, `to`, границы входят) влияет только на журнал; распределения считаются по всей библиотеке.

| Поле ответа | Что это |
| --- | --- |
| `period_from`, `period_to`, `total_items` | Период и число записей |
| `genres`, `countries` | Распределение: `name`, `items` (записей), `progress` (единиц прогресса). Жанры раскладываются по одному (`unnest`), запись с тремя жанрами попадает в три строки. Порядок: по `items`, затем `progress`, затем по имени. Длина ограничена `limit` |
| `categories`, `statuses` | То же по категориям и статусам, без ограничения |
| `years` | По годам выхода по возрастанию (записи без года не входят) |
| `top_items` | Записи с наибольшим накопленным прогрессом (не больше `limit`); записи без прогресса не входят |
| `totals` | Накоплено по библиотеке: `episodes`, `chapters`, `movies` (просмотренные фильмы) |
| `activity` | Отметки журнала по дням периода: каждый день присутствует, пустой день = 0 |
| `marks` | Отметки журнала за период по видам: серии, главы, фильмы |

Диаграммы вкусов (жанры, страны, годы) считаются по числу записей (`items`: каждая карточка = 1), поэтому фильмы, книги и тайтлы без прогресса тоже учтены. `progress` записи (нужен для `top_items`, `totals` и как справочное поле): `current_episode` для anime, cartoon, tv_series, tv_show, `current_chapter` для manga, book, audiobook, 1 для просмотренного фильма. Серии, главы и фильмы всегда считаются раздельно. `totals` строится по счётчикам записей, поэтому учитывает и прогресс, загруженный импортом, а `activity` и `marks` — только отметки, сделанные через `POST /items/{id}/progress`. Неверный период (начало позже конца, больше 366 дней) даёт `422`.

### Источники: Shikimori и AniList

У аниме и манги два источника: **Shikimori** (по умолчанию: названия и жанры по-русски) и **AniList** (ключ не нужен, лимит 90 запросов в минуту; названия английские или ромадзи, жанры переведены в те же названия, что у Shikimori; даёт оценку, общее число серий и глав прямо в списках). Остальные категории по-прежнему обслуживает один источник.

Другой источник выбирается параметром `source` (`shikimori`, `anilist`, `tmdb`, `openlibrary`): `GET /catalog/search`, `GET /catalog/popular`, `GET /items/{id}/enrich/candidates?source=`; для применения варианта (`POST …/enrich/apply`) и добавления из каталога источник берётся из тела (`source`). Без `category` и с `source` запрашиваются только основные категории, которые этот источник обслуживает. Источник, не подходящий категории, даёт `400`, неизвестный источник без категории тоже `400`. Кэш популярного ведётся отдельно по каждому источнику.

### Поиск по каталогам и добавление

`GET /catalog/search?q=Фрирен&category=anime` ищет строку у провайдера категории (те же источники и настройки, что у обогащения: `TMDB_API_KEY`, `SHIKIMORI_USER_AGENT`, необязательно `OPENLIBRARY_USER_AGENT`) и возвращает `results` (источник, `external_id`, названия, год, ссылку на постер, жанры, страну, автора) и `errors`. Без `category` ищет по основным категориям: `anime`, `tv_series`, `movie`, `manga`, `book` (у TMDB сериалы, ТВ-шоу и мультсериалы ищутся одним запросом, поэтому из них берётся только `tv_series`). Если один источник не настроен или не ответил, он пропускается, остальные результаты возвращаются, а причина попадает в `errors`. Если не ответил ни один, ответ `503` (нет настроек) или `502` (сервис недоступен), как и при обогащении. Шанс получить результаты у Shikimori и Open Library есть и без ключей TMDB.

`GET /catalog/popular?category=anime` возвращает популярное по категории в том же формате (`results`, `errors`, ошибки внешних сервисов 502 и 503 как у поиска). Источники: TMDB (`/movie/popular` для фильмов, `/discover/tv` для сериалов; мультсериалы и ТВ-шоу выбираются по жанрам, сериалы идут без анимации и телепередач), Shikimori (порядок `popularity`), Open Library (`trending/weekly`, одна подборка на книги и аудиокниги). У результата есть `rating` (оценка источника по 10-балльной шкале; у Open Library её нет). Ответ по паре «категория, лимит» держится в памяти час, ошибки не кэшируются; кэш общий для процесса и сбрасывается его перезапуском.

`POST /items/from-catalog` создаёт запись из результата поиска:

- источник должен подходить категории (`400` иначе), а провайдер должен быть настроен (`503` иначе);
- дубликат (то же русское и оригинальное название и категория, без учёта регистра) отклоняется с `409` и текстом «Уже в библиотеке: …»;
- постер скачивается только с хостов провайдеров; если он не скачался или не подошёл, запись всё равно создаётся без постера;
- жанры и общее число серий или глав подгружаются отдельным запросом (`fill_details`): Shikimori даёт жанры и `total_episodes` (аниме) или `total_chapters` (манга), TMDB даёт `total_episodes` только для завершённых сериалов (у идущих итог неизвестен). Присланные жанры не заменяются; число 0 у источника считается «неизвестно» и в базу не пишется; при ошибке запись создаётся без этих данных;
- фильм, добавленный сразу как `completed`, попадает в журнал просмотров.

### Экспорт

`GET /export?format=xlsx|json` отдаёт всю библиотеку файлом (`Content-Disposition: attachment; filename="episodio-ГГГГ-ММ-ДД.xlsx"`). Эндпоинт закрыт ключом API, как и остальные, и выгружает **всё**, включая заметки и ссылки: это личная выгрузка владельца, в отличие от публичных витрин. Неверный формат даёт `422`.

**Excel (`xlsx`).** Первый лист «Все» содержит всю библиотеку разом (с столбцами «Тип» и прогресса и серий, и глав), дальше по листу на каждую категорию, в которой есть записи (порядок: Аниме, Мультсериалы, Сериалы, Фильмы, ТВ-шоу, Манга, Книги, Аудиокниги); пустая библиотека даёт один лист «Библиотека» с заголовками. Записи на листе по алфавиту.

| Столбцы | Где |
| --- | --- |
| Название, Оригинальное название, Статус, Оценка | на всех листах |
| Сезон, Серий просмотрено, Всего серий | сериалы, аниме, мультсериалы, ТВ-шоу |
| Том, Глав прочитано, Всего глав | манга, книги, аудиокниги |
| Год выхода, Страна, Жанры, Автор, Озвучка / перевод, Дата завершения, Добавлено, Ссылка, Описание, Заметка | на всех листах |

Заголовки русские, жанры через запятую с заглавной буквы, статус по виду категории («Смотрю», «Читаю», «Слушаю» и т. д.). Оценка, год и счётчики — числа, пустые значения — пустые ячейки (не нули). Даты — настоящие даты Excel в формате `ДД.ММ.ГГГГ` (дата завершения без времени). У листов закреплена строка заголовков и включён автофильтр. Текст всегда записывается как текст: название вроде `=HYPERLINK(...)`, пришедшее из внешнего каталога, не станет формулой. Управляющие символы убираются, текст в ячейке обрезается до 32000 знаков (предел Excel 32767).

**JSON (`json`).** `{"app", "exported_at", "items", "log"}`: записи в том же виде, что отдаёт `GET /items/` (все поля, включая `raw`), и весь журнал прогресса от старых отметок к новым. Такой файл принимает и «Восстановить базу данных из файла» в настройках.

Для работы нужен `openpyxl` (есть в `requirements.txt`).

### Витрины

Витрина — публичная страница «мой топ»: **завершённые** тайтлы с оценкой, отсортированные по оценке (при равенстве выше те, что завершены позже). Период задаётся по дате завершения `finished_at`: `year` (без него за всё время) и `month` (только вместе с годом), `category` ограничивает категорию (без неё все), `max_items` — число мест (1–50). В таблице `showcases` они хранятся вместе с `slug` (адрес: латиница, цифры, дефисы), названием и флагом `is_public` (по умолчанию `false`).

| Запрос | Что делает |
| --- | --- |
| `POST /showcases` | Создать. `slug` необязателен: строится по параметрам (`top-anime-2026-03`), занятый получает суффикс `-2`, `-3`. Занятый явный адрес: `409` |
| `PATCH /showcases/{id}` | Частичное изменение; `category`, `year`, `month` можно сбросить в `null`. Месяц без года: `422` (проверяется после слияния с сохранёнными значениями) |
| `POST /showcases/preview` | Те же параметры и название в теле, ответ в формате публичного. Ничего не сохраняет; постеры отдаются путями библиотеки (`/posters/…`) |
| `GET /public/showcases/{slug}` | Публичное содержимое: `title`, `category`, `year`, `month`, `items` |

В публичный ответ входят только поля `ShowcaseItem`: названия, категория, год выхода, жанры, страна, автор, оценка, постер и дата завершения. Заметка, ссылка на источник, озвучка, описание, `raw`, прогресс и внутренние id туда не попадают (список полей закреплён тестом на утечки). Витрина с `is_public = false` и несуществующая отвечают одинаково (`404`), по ответу не видно, что адрес занят. Постеры локальных записей отдаются публичным адресом витрины, и только тех записей, которые сейчас входят в неё; внешние постеры (https) остаются как есть, другие виды адресов не показываются.

Эти эндпоинты, как и остальные, закрыты ключом API (`X-API-Key`). Публичной страницей для людей занимается фронтенд: сервер Next.js сам ходит в FastAPI с ключом, а страницу `/u/<имя>/<адрес>` отдаёт без входа (см. [Витрины во фронтенде](frontend/README.md#витрины)).

### Защита ключом API

Если в `.env` задан `API_KEY`, все эндпоинты, кроме `/`, `/health` и `/posters/...`, требуют заголовок `X-API-Key` с этим значением, иначе ответ `401`. Постеры остаются открытыми, чтобы `<img>` работал напрямую. Если `API_KEY` не задан или пуст, защита выключена. В `/docs` ключ вводится кнопкой Authorize. Фронтенд должен ходить в API через серверную часть Next.js, которая подставляет ключ (в браузер он попадать не должен).

### Ручной выбор при обогащении

Когда скрипт `scripts.enrich` не смог выбрать вариант сам (запись попала в `data/enrich_review.json`) или нужно подтянуть данные для одной записи, выбрать можно через API. Этим пользуется и интерфейс (кнопка «Найти данные» на странице тайтла и вкладка «Требуют проверки» в каталоге):

1. `GET /items/{id}/enrich/candidates` возвращает список вариантов: `source`, `external_id`, названия, год, ссылку на постер, жанры, страну, автора. Запись при этом не меняется.
2. `POST /items/{id}/enrich/apply` с `source` и `external_id` выбранного варианта заполняет **только пустые поля** карточки и скачивает постер, если его не было. В ответе приходят обновлённая карточка (`item`) и список заполненных полей (`changed`).
3. `force=true` — единственное исключение из правила «не перезаписывать»: заменяет **только постер**, остальные поля по-прежнему не трогаются.

Ошибки внешних сервисов возвращаются с понятным текстом, а не 500:

| Код | Когда |
| --- | --- |
| `503` | Обогащение не настроено (нет `TMDB_API_KEY` или `SHIKIMORI_USER_AGENT`) или источник не принял ключ |
| `502` | Внешний сервис не ответил вовремя, недоступен, вернул ошибку или файл, непригодный как постер |
| `404` | Нет записи или выбранного варианта среди результатов поиска (обнови список и выбери снова) |
| `400` | Источник не подходит для категории записи |

Выбранный вариант находится повторным поиском, поэтому выбирать нужно из свежего списка `candidates`.

## Скрипты

Все скрипты лежат в `scripts/` и запускаются из корня проекта как модули (`python -m scripts.<имя>`) при активированном `.venv`. Подключение к базе они берут из `.env` (`DATABASE_URL` или `DB_*`).

| Скрипт | Для чего |
| --- | --- |
| `scripts.init_db` | Создаёт таблицы `media_items`, `progress_log` и `showcases`, функции и триггеры по `scripts/schema.sql` |
| `scripts.import_json` | Загружает список из JSON в базу |
| `scripts.enrich` | Дополняет карточки данными из TMDB, Shikimori и Open Library: постер, жанры, страна, год, автор |
| `scripts.backup` | Резервная копия БД через `pg_dump` с ротацией |

Код возврата у всех скриптов один: `0` — всё прошло без ошибок, больше нуля — были ошибки (подробности ниже).

### `scripts.init_db` — создание структуры базы

Применяет `scripts/schema.sql` к базе одной транзакцией: если что-то пойдёт не так, база останется как была. Скрипт можно запускать сколько угодно раз, существующие данные он не трогает. В конце печатает, сколько записей сейчас в `media_items`.

```bash
python -m scripts.init_db                  # рабочая база из .env
python -m scripts.init_db --reset          # удалить таблицы и создать заново (спросит подтверждение)
```

| Опция | Что делает |
| --- | --- |
| `--database-url URL` | Применить схему к другой базе вместо базы из `.env` |
| `--reset` | Перед применением схемы удалить таблицы `media_items` и `progress_log`, триггеры и функции. **Все данные пропадут.** Скрипт спросит `y/N` и покажет, в какой базе это произойдёт |
| `--yes` | Не спрашивать подтверждение для `--reset` |

Если ответа нет (например, скрипт запущен без терминала), `--reset` считает ответ «нет» и ничего не удаляет.

### `scripts.import_json` — импорт списка

Читает один или несколько JSON-файлов с массивом записей, проверяет каждую запись теми же схемами, что и API, и добавляет в базу. Переименовывает `season`, `episode`, `volume`, `chapter` в `current_*`, пустые строки превращает в `NULL`, жанры приводит к нижнему регистру без повторов. Статус из файла не переносится: все записи получают `planned`. Дубликаты (то же название, оригинальное название и категория, без учёта регистра) пропускаются, поэтому повторный запуск безопасен. Записи с ошибками пропускаются и перечисляются в отчёте с номером и строкой `raw`, остальные загружаются.

```bash
python -m scripts.import_json data/media.json --dry-run     # проверка без записи
python -m scripts.import_json data/media.json               # импорт
python -m scripts.import_json data/anime.json data/series.json   # несколько файлов
```

| Опция | Что делает |
| --- | --- |
| `файлы` | Один или несколько JSON-файлов (обязательный аргумент) |
| `--dry-run` | Проверить файлы и посчитать результат, ничего не записывая в базу |

Код возврата `1` означает, что в файлах были записи с ошибками. Подробнее: [Импорт своего списка](#импорт-своего-списка).

### `scripts.enrich` — обогащение карточек

Ищет записи во внешних API (источник зависит от категории) и заполняет **только пустые** постер, жанры, страну, год и автора. Неоднозначные и ненайденные записи не меняет, а сохраняет в `data/enrich_review.json`. Для TMDB нужен `TMDB_API_KEY`, для Shikimori — `SHIKIMORI_USER_AGENT` в `.env`.

```bash
python -m scripts.enrich --category anime --limit 5 --dry-run
```

Опции: `--category`, `--source`, `--limit N`, `--id N`, `--dry-run`. Коды возврата: `0` — без ошибок, `1` — были ошибки, `2` — нет ключа или TMDB его не принял. Подробнее: [Обогащение карточек](#обогащение-карточек).

### `scripts.backup` — резервная копия базы

Делает `pg_dump` в формате custom и кладёт файл `episodio_ГГГГММДД_ЧЧММСС.dump` в `data/backups` (папка в git не попадает). После успешной копии удаляет лишние: хранятся последние 14. Если копия не удалась, старые не трогаются. Пароль передаётся через окружение процесса и нигде не печатается.

```bash
python -m scripts.backup                  # копия в data/backups, хранить 14 последних
python -m scripts.backup --keep 30        # хранить 30
python -m scripts.backup --dir D:\Backups # другая папка (лучше на другом диске)
```

Опции: `--dir`, `--keep N`, `--pg-dump ПУТЬ`. `pg_dump` ищется по аргументу, переменной `PG_DUMP`, в `PATH`, затем среди установок в `C:\Program Files\PostgreSQL\*\bin` (берётся самая новая). Код возврата `0` — копия создана, `1` — ошибка.

Копия `pg_dump` восстанавливается целиком (`pg_restore`). Для переноса данных в другие программы и просмотра в таблице есть [экспорт](#экспорт) в Excel и JSON.

**Постеры в копию не входят.** База хранит только путь (`/posters/42.jpg`), сами файлы лежат в `media/posters/`. Загруженные вручную постеры восстановить из внешних источников нельзя, поэтому копируйте эту папку вместе с дампом.

Восстановление в пустую базу:

```bash
pg_restore --no-owner --dbname episodio_db data/backups/episodio_20261025_030000.dump
```

**Запуск по расписанию (Планировщик заданий Windows).** Из PowerShell, раз в день в 03:00 (пути подставьте свои):

```powershell
$action  = New-ScheduledTaskAction -Execute "D:\ProjectsLab\Episodio\.venv\Scripts\python.exe" -Argument "-m scripts.backup" -WorkingDirectory "D:\ProjectsLab\Episodio"
$trigger = New-ScheduledTaskTrigger -Daily -At 3:00
Register-ScheduledTask -TaskName "Episodio backup" -Action $action -Trigger $trigger
```

Если компьютер в 03:00 выключен, включите в свойствах задачи «Запускать задачу как можно скорее после пропуска запланированного запуска». Проверить, что копии появляются, можно по папке `data/backups`.

2. Сначала проверь файл без записи в базу:

   ```bash
   python -m scripts.import_json data/media.json --dry-run
   ```

3. Если ошибок нет, запусти импорт:

   ```bash
   python -m scripts.import_json data/media.json
   ```

Все импортированные записи получают статус `planned`. Дубликаты (то же название, оригинальное название и категория, без учёта регистра) пропускаются, поэтому скрипт можно запускать повторно. Записи с ошибками пропускаются и выводятся в отчёте с номером и строкой `raw`. Если ошибки были, код возврата равен 1. Пример файла: `tests/fixtures/media_sample.json`.

## Обогащение карточек

После импорта у записей есть названия, категория, жанры, страна и год, но нет постеров. Скрипт `scripts/enrich.py` ищет каждую запись во внешних API и дополняет её пустые поля. Источник выбирается по категории записи:

| Категории | Источник | Что заполняется |
| --- | --- | --- |
| `tv_series`, `tv_show`, `movie` | [TMDB](https://www.themoviedb.org) (по умолчанию), [TheTVDB](https://thetvdb.com) (`--source tvdb`, а если ключа TMDB нет, он берётся сам) | постер, жанры, страна, год; у TMDB страна только у сериалов |
| `cartoon` | [TheTVDB](https://thetvdb.com) (по умолчанию), [TMDB](https://www.themoviedb.org) (`--source tmdb`, а если ключа TheTVDB нет, он берётся сам) | постер, жанры, страна, год |
| `anime`, `manga` | [Shikimori](https://shikimori.io) (по умолчанию), [AniList](https://anilist.co) (`--source anilist`) | постер, жанры, год; у AniList ещё страна |
| `book`, `audiobook` | [Open Library](https://openlibrary.org) | обложка, автор, год первой публикации |

### Что делает скрипт

1. Берёт записи, у которых нет постера или пусты жанры, страна либо год, и поддерживаемой категории.
2. Ищет запись у своего источника сначала по русскому названию (`title_ru`), а если совпадения нет, то по оригинальному, английскому или ромадзи (`title_original`). Если год известен, он учитывается в поиске.
3. Выбирает совпадение. Названия сравниваются без учёта регистра, пунктуации и пробелов (так «Quan zhi gao shou» и «Quanzhi Gaoshou» считаются одним названием), сначала русское название записи с названиями кандидата, потом оригинальное. Год в скобках в конце названия кандидата («The Flash (2014)») отбрасывается, год записи должен совпасть с точностью до ±1. Синонимы и другие названия, которые отдаёт источник, не используются: ошибочное совпадение хуже ненайденного. Автоматически применяется только **единственный** уверенный кандидат; остальное подбирается вручную кнопкой «Найти данные» в карточке.
4. Заполняет **только пустые поля**. Всё, что заполнено, в том числе вручную, не перезаписывается.
5. Постер скачивается в `media/posters/{id}.jpg`, а в `poster_url` записывается путь `/posters/{id}.jpg`.
6. Записи, для которых нашлось несколько подходящих вариантов или ни одного, **не меняются**: их список с кандидатами сохраняется в `data/enrich_review.json`.

### Настройка

Впиши в `.env` (шаблон есть в `.env.example`):

| Переменная | Для чего | Обязательна |
| --- | --- | --- |
| `TMDB_API_KEY` | Ключ TMDB, бесплатный: <https://www.themoviedb.org/settings/api>. Подходит и короткий «API Key», и длинный «API Read Access Token» | для категорий TMDB (если не задан, сериалы и фильмы обслуживает TheTVDB) |
| `TVDB_API_KEY` | Ключ TheTVDB v4: <https://thetvdb.com/dashboard/account/apikey> | для TheTVDB |
| `TVDB_PIN` | PIN, только для ключей с подпиской («user supported key»); для обычного проектного ключа не нужен | нет |
| `SHIKIMORI_USER_AGENT` | Название приложения, например `Episodio`. Shikimori требует подписывать им запросы | для `anime` и `manga` |
| `OPENLIBRARY_USER_AGENT` | Название приложения и контакт, например `Episodio (you@example.com)`. С контактом лимит запросов выше | нет |

Если для указанной категории нужной переменной нет, скрипт сообщает об этом и завершается с кодом 2. Если категория не указана, источники без настроек пропускаются, остальные работают.

### Как запустить

1. Сначала проверь, что изменится. В режиме `--dry-run` ничего не записывается ни в базу, ни в `media/posters/`, ни в файл проверки:

   ```bash
   python -m scripts.enrich --category anime --limit 5 --dry-run
   ```

2. Если результат устраивает, запусти по-настоящему:

   ```bash
   python -m scripts.enrich --category anime --limit 5
   ```

   Повторный запуск безопасен: уже заполненное не трогается, обрабатываются только записи, которым ещё есть что дополнить.

### Опции

| Опция | Что делает |
| --- | --- |
| `--category` | Обработать только одну категорию (`tv_series`, `tv_show`, `cartoon`, `movie`, `anime`, `manga`, `book`, `audiobook`) |
| `--source` | Только этот источник: `tmdb`, `tvdb`, `shikimori`, `anilist`, `openlibrary`. Без неё категорию обслуживает первый подходящий и настроенный (у сериалов и фильмов это TMDB, у аниме и манги Shikimori), остальные включаются явно: `--category anime --source anilist`, `--category tv_series --source tvdb` |
| `--limit N` | Обработать не больше N записей |
| `--id N` | Обработать одну запись |
| `--dry-run` | Показать, что изменится, ничего не записывая |

Без опций скрипт обрабатывает все подходящие записи. Для первого раза лучше взять небольшой `--limit`.

### Отчёт и код возврата

Для каждой записи выводится строка с результатом (какие поля заполнены, «не найдено» или «неоднозначно»), а в конце итоги: **обогащено**, **неоднозначно**, **не найдено**, **без изменений** (совпадение нашлось, но заполнять нечего) и **ошибок**. Код возврата: `0` — ошибок нет, `1` — были ошибки (например, не скачался постер), `2` — не хватает настроек или источник не принял ключ.

### Записи для ручной проверки

Файл `data/enrich_review.json` содержит для каждой неразобранной записи `id`, названия, год, причину (`ambiguous` — нашлось несколько вариантов, `not_found` — ни одного) и список кандидатов с их `external_id`, названием, годом и ссылкой на постер. Выбрать нужный вариант можно в `/docs` через `GET /items/{id}/enrich/candidates` и `POST /items/{id}/enrich/apply` (см. [Ручной выбор при обогащении](#ручной-выбор-при-обогащении)), а поля можно поправить и вручную через `PATCH /items/{id}`; свой постер загружается через `POST /items/{id}/poster`. Файл обновляется при каждом запуске без `--dry-run`: записи, обработанные в этом запуске, заменяются свежим результатом, остальные сохраняются. Запись, которую ты полностью заполнил вручную, скрипт больше не выбирает, поэтому её строку из файла можно удалить самостоятельно.

### Ограничения и лимиты

- **Частота запросов.** TMDB: не чаще 4 в секунду. Shikimori: не чаще 90 в минуту (по документации разрешено 5 в секунду и 90 в минуту). Open Library: 1 в секунду, а с `OPENLIBRARY_USER_AGENT` до 3 в секунду. При ответах 429 и 5xx и при сетевых сбоях скрипт повторяет запрос с нарастающей паузой. Для аниме и манги на каждую найденную запись приходится ещё один запрос за жанрами, поэтому большой список обрабатывается заметно дольше.
- **TMDB.** У фильмов страна не заполняется: в ответе поиска её нет. Категория `cartoon` ищется только среди сериалов, полнометражные мультфильмы могут попасть в «не найдено».
- **Shikimori.** Автор манги не заполняется: API не отдаёт его в карточке.
- **Open Library.** Жанры не заполняются. Книги с русскими названиями часто не находятся: база Open Library в основном англоязычная, лучше всего ищется по оригинальному названию и автору.

## Фронтенд

Веб-интерфейс на Next.js 16 лежит в `frontend/` (подробности: [frontend/README.md](frontend/README.md)). Библиотека и лента активности хранятся в базе, браузер получает их через API.

Запуск (два терминала, из корня проекта):

```bash
uvicorn backend.main:app --reload --host 127.0.0.1   # API на http://127.0.0.1:8000
cd frontend && npm install && npm run dev   # интерфейс на http://localhost:3000
```

В корневом `.env` для фронтенда нужны:

| Переменная | Для чего |
| --- | --- |
| `AUTH_LOGIN`, `AUTH_PASSWORD`, `AUTH_SECRET` | Вход в интерфейс (секрет: случайная строка от 32 символов) |
| `API_URL` | Адрес FastAPI, по умолчанию `http://127.0.0.1:8000` |
| `API_KEY` | Общий секрет API, если он включён на бэкенде (одно и то же значение для uvicorn и Next.js) |
| `PUBLIC_HANDLE` | Имя владельца в публичных ссылках `/u/<имя>/<адрес>` (латиница, цифры, «-», «_», по умолчанию `me`). Логин для входа в ссылки не попадает |

Браузер обращается не к FastAPI, а к своему Next.js (`/api/backend/...`): сервер Next.js проверяет сессию и подставляет `X-API-Key`, поэтому ключ в браузер не попадает. Постеры отдаются тем же путём. Первый список загружается в пустую базу так: `python -m scripts.import_json data/media.json`.

Проверки фронтенда (из `frontend/`): `npm run typecheck`, `npm test` (vitest, внешних сервисов не нужно), `npm run build`.

Ручное обогащение в интерфейсе (кнопка «Найти данные», вкладка «Требуют проверки» в каталоге) использует те же ключи, что и `scripts.enrich`: без `TMDB_API_KEY` сериалы, фильмы и ТВ-шоу отвечают 503. Подробнее: [frontend/README.md](frontend/README.md#ручное-обогащение).

## Развёртывание на сервере (Docker)

Локально проект запускается без Docker (см. «Быстрый старт»), Docker нужен только для сервера. Одна команда поднимает PostgreSQL, API, фронтенд и автобэкап. https и домен обслуживает Caddy, который уже работает на сервере отдельным контейнером: фронтенд подключается к его docker-сети, порты наружу compose не публикует.

```bash
cp .env.example .env     # заполнить: DB_PASSWORD, API_KEY, AUTH_LOGIN, AUTH_PASSWORD, AUTH_SECRET, TMDB_API_KEY (PROXY_NETWORK по умолчанию web_gateway)
docker compose up -d --build
docker compose logs -f api web
```

Если сайта ещё нет в Caddyfile вашего Caddy, добавьте его и перезагрузите конфигурацию (`docker exec <контейнер-caddy> caddy reload --config /etc/caddy/Caddyfile`):

```caddyfile
episodio.example.com {
	encode gzip
	reverse_proxy episodio-app:3000
}
```

Домен должен указывать на сервер, сертификат Caddy получит сам. Если Caddy запущен не в docker-сети с именем из `PROXY_NETWORK`, подключение не сработает: `docker compose up` сообщит, что сеть не найдена.

| Сервис | Что делает |
| --- | --- |
| `db` | PostgreSQL 16, данные в томе `pgdata`; схема применяется при старте API (`scripts.init_db`) |
| `api` | FastAPI; снаружи недоступен, к нему ходит только `web`. Постеры в папке хоста `./media/posters` (владелец uid 1000: `sudo chown -R 1000:1000 media/posters`), файл ручной проверки обогащения `/app/data/enrich_review.json` в томе `appdata` (прочитать: `docker compose exec api cat /app/data/enrich_review.json`) |
| `web` | Next.js, ходит в `api` по `http://api:8000` и подставляет `API_KEY`; для Caddy доступен как `episodio-app:3000` |
| `backup` | Раз в `BACKUP_INTERVAL_HOURS` часов (24) кладёт в `./backups` дамп `episodio_*.dump` и архив постеров `posters_*.tar.gz`, хранит `BACKUP_KEEP` последних (14) |

Подключение к базе в контейнерах задают `DB_USER`, `DB_PASSWORD`, `DB_NAME` из `.env`; `DB_HOST` и `API_URL` compose подставляет сам, `DATABASE_URL` в `.env` игнорируется. `API_KEY` и `AUTH_*` обязательны: сервер открыт в интернет.

**Перенос текущей базы на сервер.** На старом компьютере: `python -m scripts.backup`, дальше скопируйте файл `.dump` и папку `media/posters` на сервер. На сервере (после `docker compose up -d`):

```bash
docker compose cp episodio_20261025_030000.dump db:/tmp/e.dump
docker compose exec db sh -c 'pg_restore --no-owner --clean --if-exists -U "$POSTGRES_USER" -d "$POSTGRES_DB" /tmp/e.dump'
cp -a posters/. media/posters/ && sudo chown -R 1000:1000 media/posters
```

(`posters` в последней команде — папка с вашими постерами, скопированная на сервер; `media/posters` — папка проекта, которую compose подключает в `api`.)

**Если постеры уже лежат в Docker-томе `episodio_posters`** (старая схема) и их нужно перенести в `./media/posters`. Из папки проекта на сервере, до `git pull` и `docker compose up -d --build`:

```bash
docker compose stop api web
mkdir -p media/posters
docker run --rm -v episodio_posters:/src:ro -v "$PWD/media/posters:/dst" alpine sh -c 'cp -a /src/. /dst/ && chown -R 1000:1000 /dst'
ls media/posters | wc -l      # число файлов должно совпасть с томом
docker run --rm -v episodio_posters:/src:ro alpine sh -c 'ls /src | wc -l'
```

Старый том после проверки можно удалить: `docker volume rm episodio_posters`.

**Первичная загрузка списков из JSON (пустая база на сервере).** Папки `docs/` и `data/` в git не попадают и в образ не входят (`.gitignore`, `.dockerignore`), поэтому файлы копируются вручную, а импорт запускается внутри контейнера `api`. С компьютера (пути и адрес замените на свои):

```bash
ssh user@server "mkdir -p ~/episodio/import"
scp data/media.json user@server:~/episodio/import/media.json
```

На сервере, в папке проекта:

```bash
docker compose cp import/media.json api:/tmp/media.json
docker compose exec api python -m scripts.import_json /tmp/media.json --dry-run   # проверка без записи
docker compose exec api python -m scripts.import_json /tmp/media.json             # импорт
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select category, status, count(*) from media_items group by 1,2 order by 1,2"'
docker compose exec api rm /tmp/media.json && rm -r import
```

Можно передать несколько файлов сразу (`/tmp/anime.json /tmp/cartoon.json ...`). Повторный запуск безопасен: дубликаты (русское и оригинальное название + категория) пропускаются. Записи с ошибками (например, `title_ru: null`, поле обязательное) пропускаются и перечисляются в отчёте, остальные загружаются; поправьте JSON и запустите импорт ещё раз. Статус не переносится: все записи получают `planned`. Постеры и описания импорт не подтягивает: после него запустите `docker compose exec api python -m scripts.enrich --category anime --limit 5 --dry-run` (нужны ключи в `.env`), затем без `--dry-run`.

**Восстановление из автобэкапа** — те же команды `pg_restore` с файлом из `./backups`, постеры: `sudo tar -xzf backups/posters_….tar.gz -C media/posters && sudo chown -R 1000:1000 media/posters`. Обновление версии: `git pull && docker compose up -d --build`. Копии из `./backups` стоит периодически забирать с сервера на другой диск.

## Тесты

Тесты бэкенда (фронтенд проверяется отдельно, см. выше). Перед первым запуском:

1. Активируй `.venv` (см. быстрый старт).
2. Убедись, что PostgreSQL запущен и в нём создана пустая база `episodio_test`.
3. Задай в `.env` строку `TEST_DATABASE_URL`, например `postgresql+psycopg2://postgres:postgres@localhost:5432/episodio_test`. Схему создавать вручную не нужно: `pytest` сам применяет `scripts/schema.sql`.

Команды (из корня проекта):

```bash
pytest                           # все тесты
pytest -v                        # с названиями тестов
pytest -rs                       # показать причины пропущенных (skipped) тестов
pytest tests/test_schemas.py     # только схемы, база не нужна
pytest tests/test_api.py         # только API
pytest tests/test_progress_api.py tests/test_schema_changes.py   # прогресс, журнал, жанры, ключ API, триггер finished_at
pytest tests/test_catalog_api.py tests/test_catalog_popular.py # поиск, популярное и добавление из каталога (сеть не нужна)
pytest tests/test_stats.py       # статистика
pytest tests/test_showcases.py   # витрины
pytest tests/test_export.py      # экспорт в Excel и JSON
pytest tests/test_docs.py        # docs/plan.md совпадает со schema.sql, requirements.txt и модулями backend
pytest tests/test_anilist.py     # AniList и выбор источника
pytest tests/test_tvdb.py        # TheTVDB и запасной выбор источника (без сети)
pytest tests/test_import.py      # только импорт
pytest tests/test_posters.py     # только постеры
pytest tests/test_enrich.py tests/test_enrich_providers.py tests/test_enrich_api.py   # только обогащение (сеть не нужна)
pytest -k "dry_run"              # только тесты, в названии которых есть dry_run
pytest -x                        # остановиться на первой ошибке
```

Тесты API работают с настоящей PostgreSQL из `TEST_DATABASE_URL` (массивы и ограничения есть только в ней). Перед каждым тестом таблица в тестовой базе очищается, поэтому эта база не должна совпадать с рабочей. Если `pytest` увидит совпадение, он остановится. Если `TEST_DATABASE_URL` не задана или база недоступна, тесты с базой пропускаются, а остальные выполняются.
