# Контракт фронтенд ↔ бэкенд

> **Исторический документ.** Он описывает аудит до реализации (разделы 1–5 показывают состояние «до»). Актуальный статус, контракт и план работ: [roadmap_frontend_v2.md](roadmap_frontend_v2.md).

Черновик для подключения Next.js-фронтенда к FastAPI. Код не менялся: документ составлен по чтению
`frontend/src/lib/{types,store,rules,showcase,epi}.ts`, экранов `stats`, `feed`, `catalog`,
а также `backend/{schemas,models,main}.py` и `scripts/schema.sql`.

Условные обозначения: **FE** — фронтенд (`Title` из `types.ts`), **BE** — бэкенд (`MediaItem`).
«NULL» — поле может отсутствовать; `?` в TypeScript означает `undefined`.

## 1. Поля: фронтенд ↔ бэкенд

| FE-поле | FE-тип | Обяз. на FE | BE-поле | BE-тип (БД) | Nullable в БД | Комментарий |
|---|---|---|---|---|---|---|
| `id` | `number` | да | `id` | `SERIAL` (int32) | нет | FE сейчас генерирует `Date.now()` (~1.7·10¹²) — **не влезает в int32**. После подключения id выдаёт только БД |
| `type` | `TitleType` (5 значений) | да | `category` | `VARCHAR(50)`, CHECK (8 значений) | нет | см. раздел 2 |
| `st` | `TitleStatus` | да | `status` | `VARCHAR(50)`, CHECK, default `planned` | нет | см. раздел 2 |
| `t` | `string` | да | `title_ru` | `VARCHAR(255)` | нет | |
| `en` | `string?` | нет | `title_original` | `VARCHAR(255)` | да | FE хранит пустую строку `""`, BE — `NULL`: адаптер должен приводить `"" ↔ null`. Название «English» на FE ≠ гарантированно английское, в BE это оригинал (может быть японским) |
| `desc` | `string?` | нет | — | — | — | **нет в БД** |
| `img` | `string?` | нет | `poster_url` | `TEXT` | да | FE: dataURL или путь. BE: путь `/posters/42.jpg` (относительный, нужен префикс адреса API) или внешний URL. dataURL в БД класть нельзя — загружать через `POST /items/{id}/poster` |
| `y` | `number` | да | `release_year` | `INTEGER` | да | FE при пустом значении подставляет текущий год (`saveTitle`) или `0` (`parseBackup`); BE допускает `NULL` |
| `c` | `string` | да | `country` | `VARCHAR(100)` | да | FE при пустом подставляет `"—"`; адаптер: `"—" ↔ null` |
| `g` | `string[]` | да | `genres` | `TEXT[]`, default `{}` | да (default `{}`) | FE: «Экшен», с заглавной, по умолчанию `["Без жанра"]`. BE при фильтре сравнивает в **нижнем регистре** (`genre.strip().lower()`), провайдеры обогащения тоже кладут жанры по-своему. Нужна нормализация регистра и словаря в одном месте |
| `se` | `number?` | нет (форма даёт `1`) | `current_season` | `INTEGER ≥ 0` | да | FE по умолчанию `1`, BE по умолчанию `NULL`. Только для anime/series |
| `ep` | `number` | да | `current_episode` **или** `current_chapter` | `INTEGER ≥ 0` | да | **Одно FE-поле на два BE-поля**: для anime/series/movie → `current_episode`, для manga/book → `current_chapter`. FE `0` ↔ BE `NULL` |
| `tot` | `number` | да | — | — | — | **нет в БД** («всего серий/глав») |
| `pg` | `number?` | нет | — | — | — | **нет в БД** (прочитано страниц) |
| `pgTot` | `number?` | нет | — | — | — | **нет в БД** (всего страниц) |
| `rate` | `number?` | нет | `rating` | `INTEGER 1–10` | да | FE: `0` = нет оценки, BE: `NULL`. Адаптер: `0 ↔ null` |
| `rv` | `Review[]?` | нет | `comment` | `TEXT` | да | FE: массив отзывов `{a, t, r}`; BE: один текст. Не соответствует, см. раздел 3 |
| `h` | `[number, number]` | да | — | — | — | Оттенки градиента-заглушки постера. Чисто визуальное; можно вычислять из `id` на FE |
| — | — | — | `title_original` | | | см. `en` |
| — | — | — | `author` | `VARCHAR(255)` | да | **есть в БД, нет на FE** (автор/мангака/писатель) |
| — | — | — | `current_volume` | `INTEGER ≥ 0` | да | **есть в БД, нет на FE** (том) |
| — | — | — | `translation` | `VARCHAR(255)` | да | **есть в БД, нет на FE** (озвучка) |
| — | — | — | `source_link` | `TEXT` | да | **есть в БД, нет на FE** |
| — | — | — | `raw` | `TEXT` | да | служебное, из импорта; FE не нужно |
| — | — | — | `created_at`, `updated_at` | `TIMESTAMP` | нет | FE не использует; пригодятся для «Продолжить» и ленты |

Отдельно (не поля тайтла, живут только на FE): `lastId` (карточка «Продолжить»), `savedAt`
(время последней резервной копии), `theme`, `lang`, `pulse`, `toast`, `palOpen`, `hydrated`.

### Правила, которые сейчас зашиты во фронтенде и затрагивают поля

- `fixSt`: `ep >= tot` → `done`; начатое (`ep > 0`) из `planned` → `watching`.
- `statusPatch`: ручной статус `done` ставит `ep = tot`, `planned` сбрасывает `ep = 0`.
- `saveTitle`: для фильма `tot = 1`; `pgTot` только у книг; `se` только у anime/series.
- Книга на FE имеет **два** счётчика: главы (`ep/tot`) и страницы (`pg/pgTot`). В БД есть только `current_volume`/`current_chapter`.

## 2. Значения

### Категории

| FE `type` | BE `category` | Примечание |
|---|---|---|
| `anime` | `anime` | |
| `series` | `tv_series` | |
| `movie` | `movie` | |
| `book` | `book` | |
| `manga` | `manga` | |
| — | `cartoon` | нет на FE |
| — | `tv_show` | нет на FE |
| — | `audiobook` | нет на FE |

Обратное направление (BE → FE) для категорий, которых нет на FE, сейчас не определено: `cartoon`, `tv_show` → `series`?
`audiobook` → `book`? (см. вопросы). Пока в БД есть записи этих категорий, адаптер обязан что-то с ними сделать, иначе
`TYPES.find(...)` и `unitOf` отработают по значению по умолчанию («Аниме»).

### Статусы

| FE `st` | BE `status` | Подпись на FE |
|---|---|---|
| `watching` | `watching` | «Смотрю» / «Читаю» (для book/manga) |
| `planned` | `planned` | «В планах» |
| `done` | `completed` | «Просмотрено» / «Прочитано» |
| `dropped` | `dropped` | «Брошено» |

Совпадает 1 к 1, различается только `done ↔ completed`.

### Прочие значения

| Что | FE | BE |
|---|---|---|
| Нет оценки | `0` | `NULL` |
| Нет оригинального названия | `""` | `NULL` |
| Нет страны | `"—"` | `NULL` |
| Нет жанров | `["Без жанра"]` | `[]` |
| Нет прогресса | `ep = 0` | `NULL` |
| Единица прогресса | `unitOf(type)`: `ep` / `ch` / `film` | зависит от `category`: `current_episode` / `current_chapter` |
| Идентификатор | `number` (`Date.now()`) | `int32` serial |
| Время | строка `"HH:MM"` + `day: "СЕГОДНЯ"` в логе | `TIMESTAMP` без часового пояса |

## 3. Есть на фронтенде, нет в БД

| Что на FE | Где используется | Что нужно в БД |
|---|---|---|
| **Описание** `desc` | карточка, форма, экспорт | колонка `description TEXT` (может заполняться обогащением из TMDB/Shikimori/Open Library) |
| **«Всего серий/глав»** `tot` | прогресс-бар, `fixSt`, `statusPatch`, «осталось», Эпи, рекомендации | колонки `total_episodes`, `total_chapters` (или одна универсальная `total_units`) |
| **Страницы** `pg`, `pgTot` | только книги | `current_page`, `total_pages` (если оставляем) |
| **Отзывы** `rv: Review[]` | карточка тайтла: список отзывов, «Добавить отзыв» | таблица `reviews(id, item_id, text, rating_at_time, created_at)`; либо схлопнуть в `comment` |
| **Журнал просмотров** `log: LogEntry[]` | лента `/feed`, «Продолжить», Эпи | таблица `progress_log(id, item_id, unit, number, logged_at)` |
| **Дата завершения** (неявно) | витрина `/showcase` — топ по году/месяцу | `finished_at DATE` (или вычислять из `progress_log`/`updated_at` — см. вопросы) |
| **Сезон по умолчанию 1** | форма | не колонка, а правило адаптера: `NULL ↔ 1` |
| **Градиент `h`** | заглушка постера | не нужно, вычислять из `id` |
| **Тип «сериал» без деления** | `series` | в БД три категории: `tv_series`, `cartoon`, `tv_show` |
| **Каталог (раздел «Обзор»)**: рейтинг `r`, популярность `p`, статус выхода `s` (`o`/`d`/`s`), число серий, жанры | `/catalog` | это не библиотека пользователя, а внешний каталог; в `media_items` ему не место |
| **Резервная копия / восстановление** | настройки | на БД не завязано (JSON-файл), но восстановление должно писать в БД, а не в localStorage |
| **Тема, язык, команда-палитра, тосты** | везде | остаётся на FE |

Обратная сторона: колонки, которые есть в БД, но FE пока не показывает — `author`, `current_volume`,
`translation`, `source_link`, `raw`, `created_at`/`updated_at`.

## 4. Эндпоинты, которых не хватает экранам

Уже есть в `backend/main.py`: `GET /items/` (фильтры `category`, `status`, `genre`, `q`; без пагинации и
сортировки, всегда `updated_at DESC`), `GET/PATCH/DELETE /items/{id}`, `POST /items/`,
`POST/DELETE /items/{id}/poster`, `GET /items/{id}/enrich/candidates`, `POST /items/{id}/enrich/apply`, `GET /health`.

| Экран / действие | Чего не хватает | Предложение |
|---|---|---|
| Главная, «Продолжить» (`lastId`) | понятия «последний тронутый тайтл» | `GET /items/?status=watching&limit=1` + сортировка по `updated_at` (уже есть как порядок по умолчанию); или поле из `progress_log` |
| Кнопка «+1 серия» (`mark`) | атомарной отметки, которая меняет прогресс, статус и пишет в журнал | `POST /items/{id}/progress` `{delta: 1}` → возвращает тайтл и запись журнала. Не гонять через голый PATCH, иначе журнал и прогресс разойдутся |
| Кнопка «−1» (`minus`) | то же в обратную сторону | тот же эндпоинт с `delta: -1` (журнал: удалять последнюю запись или не трогать — вопрос) |
| Лента `/feed` | вообще нет журнала; бесконечный скролл по 20 | `GET /log?limit=20&before=<cursor>` |
| Статистика `/stats` | агрегатов: жанры, страны, годы выхода, топ по сериям (всё считается **по просмотренным сериям**, а не по числу тайтлов) | `GET /stats` (см. раздел 5, пока можно считать на FE) |
| Витрина `/showcase` (топ-4 по категории/году/месяцу) | оценки с датой, сейчас демо-данные | `GET /showcase?category=&year=&month=` (нужна дата завершения/оценки) |
| Каталог «Обзор»: полки, баннеры, автодополнение | нет внешнего каталога; провайдеры в `backend/enrich/` ищут только **по существующей записи** (`provider.search(db_item)`), а не по свободной строке | `GET /catalog/search?q=&type=&genre=&year=&air=&sort=` и `GET /catalog/popular`, `GET /catalog/{source}/{external_id}` поверх провайдеров |
| «Добавить из каталога» (`addFromCatalog`) | создание записи из внешнего кандидата с постером | `POST /items/from-catalog` `{source, external_id, status}` (создаёт запись и применяет кандидата) |
| Моя библиотека: фильтры по типу/статусу | есть (`category`, `status`), но без `limit/offset` и сортировки | добавить `limit`, `offset`, `sort` |
| Подсказки при поиске | `q` есть, но ищет только по названию, возвращает целые карточки | достаточно существующего `GET /items/?q=` для библиотеки |
| Список жанров для фильтра (`ALL_GENRES`) | жанры захардкожены на FE (8 штук) | `GET /genres` (distinct из `media_items.genres`) — по желанию |
| Экспорт `.xlsx` | сейчас строится на FE (`exportRows`) | серверный экспорт — на будущее, не нужен для первой интеграции |
| Восстановление из резервной копии (`restore`/`parseBackup`) | массовая загрузка | `POST /items/bulk` или повторное использование `scripts/import_json` |
| Рекомендации («AI рекомендует вам», Эпи) | жанровые веса библиотеки + внешний каталог | пока считать на FE по ответу каталога; LLM — отдельный этап |
| Эпи (чат) | нет | отдельный этап, вне этого контракта |
| Вход | логин/пароль только на FE (cookie в `/api/auth/*`), в FastAPI **нет авторизации**, CORS открыт на `localhost:3000/5173` | решить, кто проверяет сессию при запросах к API (см. вопросы) |

## 5. Предложение: что в бэкенд, что оставить на фронтенде

### Добавить в БД и бэкенд (одним изменением `schema.sql` + `models.py` + `schemas.py`, по правилам проекта)

1. `media_items.description TEXT` — описание.
2. `media_items.total_episodes INTEGER CHECK (>= 0)` и `total_chapters INTEGER CHECK (>= 0)` — «всего»; без них не работают прогресс-бар и автостатус.
3. Таблица `progress_log(id, item_id → media_items ON DELETE CASCADE, unit, number, logged_at)` — журнал для ленты, «Продолжить», статистики по периодам.
4. `media_items.finished_at` — для витрины; выставляется автоматически при переходе в `completed`, сбрасывается в `NULL` при смене на другой статус.
5. Эндпоинты: `POST /items/{id}/progress`, `GET /log`, `GET /genres`, `limit/offset/sort` в `GET /items/`.
6. Нормализация жанров на BE: хранение и ответы строго в нижнем регистре.
7. Защита API общим секретом `X-API-Key` из `.env` (если переменная задана).
8. Отложено на второй этап: `GET /catalog/search`, `GET /catalog/popular`, `POST /items/from-catalog`, `POST /items/bulk` (импорт идёт через `scripts/import_json`).

Не добавляем: `current_page` / `total_pages`, таблицу `reviews`.

### Оставить на фронтенде

- Тема, язык, словарь `t("...")`, тосты, палитра, анимации, градиентные заглушки (`h`).
- Слой-адаптер `src/lib/api.ts`: переименование полей, `done ↔ completed`, `series ↔ tv_series`, `0 ↔ null`, `"" ↔ null`, `ep ↔ current_episode/current_chapter`, префикс адреса API для `poster_url`. Компоненты в API не ходят (правило проекта).
- Правила `fixSt` / `statusPatch` — вычисляются на FE и отправляются в BE готовым `PATCH` (`status` + прогресс одним запросом). Дублировать их на BE не обязательно; BE достаточно валидировать границы.
- Статистика на первом этапе: библиотека — сотни записей, `tally` и `yearBucket` на FE дёшево считаются по загруженному списку. Серверный `/stats` нужен, только когда понадобится «по периодам» (тогда нужен журнал).
- Рекомендации по жанрам (`recommend`) и «Эпи» по правилам — пока на FE, поверх ответа каталога.
- Экспорт `.xlsx` и JSON-бэкап — на FE, пока нет серверного экспорта.
- Авторизация сессии (cookie) — как сейчас, через `AUTH_*`.

### Предлагаемый порядок

1. Миграция схемы (п. 1–2 выше) и `api.ts` с чтением/созданием/PATCH/удалением; localStorage остаётся как резерв.
2. `POST /items/{id}/progress` + таблица журнала → ожила лента и «Продолжить».
3. Постеры через `POST /items/{id}/poster`.
4. Каталог через провайдеры.
5. Статистика по периодам и витрина.

## 6. Принятые решения

| № | Тема | Решение |
|---|---|---|
| 1 | «Всего» | Колонки `total_episodes` и `total_chapters` (симметрично `current_*`), плюс `description TEXT` |
| 2 | Страницы книг | Отказ: `pg`/`pgTot` убираются с FE. Прогресс книг и манги — по главам (`current_chapter` / `total_chapters`). В интерфейс выводятся `current_volume`, `author`, `translation`, `source_link` |
| 3 | Отзывы | Таблицы `reviews` нет. `comment` — единая личная заметка/рецензия. На FE `rv: Review[]` заменяется одним полем заметки |
| 4 | Категории | Все 8 категорий БД становятся категориями UI: добавляются `cartoon` (Мультсериалы), `tv_show` (ТВ-шоу), `audiobook` (Аудиокниги). Маппинг `series ↔ tv_series` остаётся |
| 5 | Журнал | Таблица `progress_log` на сервере. `delta: -1` удаляет последнюю запись журнала по этому тайтлу |
| 6 | Витрина | `media_items.finished_at`, ставится при переходе в `completed`, сбрасывается в `NULL` при смене статуса |
| 7 | Фильм | В БД прогресс `NULL`, завершённость — только статус `planned` / `completed`. Счётчик `0/1` для UI строит адаптер FE по статусу |
| 8 | Жанры | В БД и API — строго нижний регистр, на FE — с заглавной. `GET /genres` (distinct из БД). Пустой `[]` не превращается в «Без жанра» при отправке на BE |
| 9 | Каталог | Этап 1: «Обзор» остаётся статическим. Живой `GET /catalog/search` поверх провайдеров — отдельный шаг после работающей библиотеки |
| 10 | Авторизация | Общий секрет из `.env` в заголовке `X-API-Key`; проверка включается, только если переменная задана |
| 11 | Миграция | Демо-данные из localStorage не переносятся. Чистая БД, реальный список — через `scripts/import_json` |

### Следствия для контракта

- **Прогресс по категориям.** `anime`, `cartoon`, `tv_series`, `tv_show` → `current_season`, `current_episode` / `total_episodes`.
  `manga`, `book`, `audiobook` → `current_volume`, `current_chapter` / `total_chapters`. `movie` → прогресс `NULL`.
  Единица в `unitOf` и журнале (`ep` / `ch` / `film`) определяется категорией; `isReading` и `hasSeasons` в `rules.ts` придётся расширить на новые категории.
- **`fixSt` и `statusPatch`.** Для фильма логика `ep >= tot` заменяется статусом: «отметить просмотр» = перевод в `completed`.
- **Постеры.** `poster_url` относительный (`/posters/42.jpg`), а `<img>` не умеет слать заголовок `X-API-Key`. Статику `/posters` придётся оставить открытой или отдавать через прокси Next.js.
- **Правило проекта «любое изменение таблицы = `schema.sql` + `models.py` + `schemas.py` одновременно»** относится к пунктам 1, 3, 4 и 6. Alembic не добавляем, `schema.sql` идемпотентный, поэтому для существующей БД понадобятся `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.

### Остаётся уточнить при реализации

1. **`finished_at`: где ставить.** Триггер в БД надёжнее (работает и при импорте, и при любом PATCH), но тогда логика уйдёт из Python в SQL. Либо код в `update_item` / `create_item`. Рекомендация: триггер в `schema.sql`, рядом с `set_updated_at`.
2. **`delta: -1` при пустом журнале** (например, прогресс пришёл из импорта): уменьшать счётчик без удаления записи, или вернуть ошибку?
3. **`delta: +1` для `movie`.** Эндпоинт прогресса для фильма не применим: оставить отдельное действие «отметить просмотр» (PATCH статуса) с записью в журнал, или не писать фильм в журнал?
4. **`X-API-Key` и браузер.** Ключ нельзя хранить в клиентском JS (виден всем). Ходить в API через серверные route handlers / rewrites Next.js, которые подставляют ключ из `.env`?
5. **Названия новых категорий** в словаре `dict.ts`: «Мультсериал», «ТВ-шоу», «Аудиокнига» — устраивают?

---

### Решения по остальным вопросам

- `finished_at` ставит триггер БД `set_finished_at` (по аналогии с `set_updated_at`).
- `delta: -1` при пустом журнале не даёт ошибки: счётчик уменьшается (не ниже 0), последняя запись журнала удаляется, только если она есть.
- Фильм пишется в журнал (`unit = movie`, `number = 1`) при переходе в `completed`; при возврате в другой статус последняя запись удаляется.
- Запросы к API идут через серверный прокси Next.js (подставляет `X-API-Key`); `GET /posters/...` и `GET /health` открыты без ключа. Прокси фронтенда отдаёт и постеры (`/api/backend/posters/...`), поэтому FastAPI из браузера напрямую не нужен.
- Названия новых категорий: «Мультсериал» / «Мультсериалы», «ТВ-шоу», «Аудиокнига» / «Аудиокниги» (английские переводы в `i18n-core.ts`).

## 7. План работ

Статус: пункты 1, 2, 3 и 4 готовы целиком: store подключён к API, каталог ищет через `GET /catalog/search` поверх провайдеров, а найденное добавляется через `POST /items/from-catalog`.

Остаётся за рамками этого плана:

- полки «Обзора» (популярное, топ по жанру, рекомендации) пока статические: у внешних источников нет готовых подборок;
- фильтры каталога (жанр, год, статус выхода, сортировка) работают только по статической подборке;
- общее число серий и глав (`total_*`) при добавлении из каталога не заполняется: в результатах поиска его нет;
- статистика по периодам и витрина (`/showcase`) всё ещё считаются на клиенте или на демо-данных, хотя на сервере уже есть `finished_at` и `progress_log`.

1. `schema.sql` + `models.py` + `schemas.py` (+ тесты): `description`, `total_episodes`, `total_chapters`, `finished_at`, `progress_log`, нижний регистр жанров.
2. `GET /genres`, `POST /items/{id}/progress`, `GET /log`, пагинация/сортировка `GET /items/`, проверка `X-API-Key`.
3. Фронтенд: `src/lib/api.ts` (адаптер), 8 категорий, удаление страниц и `rv`, вывод `volume` / `author` / `translation` / `source_link`, заметка вместо отзывов.
4. Подключение store к API (с vitest-тестами адаптера), затем каталог поиском (этап 2).
